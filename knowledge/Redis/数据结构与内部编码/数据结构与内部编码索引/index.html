数据结构与内部编码索引

本页用途

本主题回答”Redis 里的数据到底怎么存、为什么占了这么多内存”。是全库的地基——内存管理与过期淘汰策略 的淘汰、RDB 与 AOF 两种持久化机制 的 fork COW，都依赖这里的基础概念。

MySQL 那套里 Redis 没有”索引”对应物，所以这个位置由”内部编码”补上——它承担 MySQL 中”存储引擎 + 索引实现”的同等角色。

本篇笔记

笔记内容什么时候读
Redis 数据结构与底层编码5 种基本类型 → 底层编码映射、三种 String 编码、listpack/quicklist/skiplist/intset、切换阈值与不可逆性排查内存超标、OOM、选择数据结构前

关键结论

  1. 一个类型 ≠ 一个编码。每种基本类型都有小规模和大规模两套编码，随数据量自动切换
  2. String 的 44 字节是硬编码常量（jemalloc 分配档位决定），无法通过配置修改
  3. listpack 在 7.0 取代 ziplist：省掉每节点的 prevlen，支持尾部预留空间。配置名也随之从 *-ziplist-* 改为 *-listpack-*
  4. ZSet 大规模用 skiplist + hashtable 双结构——同时支持按 member 点查和按 score 范围查，内存翻倍是最大成本
  5. 所有编码切换都是单向不可逆的。删除元素不会退回紧凑编码，因为 Redis 无法预判这次超阈值是否临时
