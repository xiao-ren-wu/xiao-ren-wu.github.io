RocketMQ 可靠性与投递语义索引

本页用途

本主题回答三个问题：消息会在哪些环节消失、每个环节对应的保障手段是什么、以及这套系统能给出的去重与一致性承诺到哪为止。前面的主题讲 RocketMQ 怎么工作，本主题把它们收敛成可承诺的边界：哪些是配置能买到的，哪些是原理上就不给的。读完能独立讲清「我的系统会不会丢消息」「重复了怎么办」「为什么说没有 exactly-once」这三个问题。

关键结论

  1. 返回成功、落盘、有副本、能读到，是四件不同的事。 「发送成功」最多覆盖到字节进入 CommitLog 的内存映射区；异步刷盘下不保证落盘，更不保证从节点已有或消费条目已建。讨论可靠性时必须指明覆盖到哪一层。RocketMQ 5.x 源码默认 flushDiskType 是 ASYNC_FLUSH、brokerRole 是 ASYNC_MASTER，所以默认部署下「返回成功但未落盘」是常态而不是例外。
  2. 消费端只有两个选项，没有第三栏。 位点提交写 Broker、业务处理写数据库，两次操作没有共同事务，所以只能选 at-most-once 或 at-least-once。默认选 at-least-once，理由是重复可去重，丢失不可恢复。
  3. RocketMQ 没有端到端 exactly-once，业务幂等是前置条件而不是优化项。 两个「正常结果」相乘：生产侧重试默认不去重，消费端为不丢失必须先处理后提交位点。事务消息对齐的是「消息终态」与「本地事务终态」，不覆盖消费侧。
  4. 消息 ID 是定位符，不是幂等键。 它在「同一客户端标识、同一写入序列、未重放」的范围内可靠；跨出这个范围，同一条业务消息可能拿到不同 ID，不同业务消息也可能撞上同一个 ID。后者会主动制造丢失，比重复更危险。判重键要用业务唯一键。
  5. 两套库的能力恰好互补，各自拥有对方没有的那一半。 Kafka 有幂等生产者与事务与 read_committed 但管不到业务本地事务，RocketMQ 有事务消息与顺序消息与延时消息但没有生产端判重。两边给出的 exactly-once 边界都止步于消息系统内部。

一条消息的可靠性边界

学习顺序

  1. 先读 消息丢失场景与保障，它是本主题的主干。把「生产端四类丢失点、Broker 端四层落点、消费端两种顺序」这条主线建立起来，后一篇的所有内容都是在补这条主线的边界。
  2. 再读 事务边界与去重约束，它回答的是「为什么光靠配置不够」。事务消息的能力边界、消息 ID 的有效范围、两个库的能力对照，都建立在第一篇的判定规则之上。
  3. 回到 刷盘策略与内存映射，把第一篇第二层的刷盘机制补细，理解页缓存、内存映射与刷盘档位为什么是三个不同的东西。
  4. 接着读 主从复制与故障转移，把第三层落点的复制档位与主从切换风险补上，并注意 Controller 模式与已弃用的 DLedger 模式的版本差异。
  5. 再读 消费模式、位点管理与推送拉取，把消费端两种顺序的机制细节、推送与拉取各自的位点行为补全。
  6. 最后读 重试、死信与消费堆积，把消费失败之后的重试路径与死信收口接上。重试不解决重复，它只是把重复往后推。
  7. 对照读 复制模型与 ISR 与 幂等、acks 与事务，把两套库的故障模型与能力差异并排看一遍，这是本主题最容易被追问的部分。
  8. 收尾读 投递语义与消息去重，确认三档语义的说法与本主题的 effectively-once 结论一致。

常见误区

  • 把「发送成功」当成「消息已落盘」。 成功只覆盖到内存映射区，异步刷盘下连落盘都不保证，而异步刷盘正是 5.x 的源码默认档位。这一条是本主题的地基，见 刷盘策略与内存映射。
  • 把刷盘超时与复制超时当成失败直接重发。 它们属于「不确定」，重发的代价是重复而不是找回消息，见 发送流程、可靠性配置与重试。
  • 认为同步刷盘解决了主从切换的风险。 刷盘管单机整机掉电，复制管主节点故障切换，异步复制下主已确认而从尚未同步的窗口是真实存在的，见 主从复制与故障转移。
  • 把事务消息说成「解决了分布式事务」。 它对齐的是消息终态与本地事务终态，管不到消费端重复，也管不到跨系统副作用，见 事务边界与去重约束。
  • 拿消息 ID 或队列内偏移当去重键。 二者在重放与客户端标识变化时都会失稳，其中偏移撞号会主动制造真实消息的丢失。
  • 认为重试保证了不重复。 生产侧重试在默认配置下不去重，重复是正常结果而不是异常，见 幂等、acks 与事务。
  • 把 Kafka 的四件套当成跨系统的 exactly-once。 它只在 Kafka 边界内成立，跨到数据库那一跳仍然需要业务幂等，见 投递语义与消息去重。
  • 拿两套库的默认值横向比较。 两边都随版本变化，必须各自查各自版本的文档。
