二叉树索引

本页用途

二叉树是递归训练的最佳场地：它的递归深度天然等于树高，每一层都有「左 / 右」两个分支，递归终止条件清晰。写树题的过程，本质是在练习**“定义清楚一个递归函数做什么”。 本主题 7 篇全是中等及以下难度，但覆盖了树题的全部基本形态**：层序（BFS）、前中后序（DFS）、BST 特化、以及”返回值 + 全局变量”的双线写法。二叉树中的最大路径和 是本库唯一的困难树题，也是「后序 + 返回贡献值」这个重要范式的唯一样本。

读完本页你应该能自己回答：什么题用 BFS、什么题用 DFS 的后序遍历；为什么求路径和要用全局变量而不是返回值；二叉树中的最大路径和 那个”向父节点返回贡献值”的设计动机。

关键结论

一、BFS vs DFS：按「答案形状」选，不按习惯选

BFS 的层边界怎么控制

标准写法是进入每层前先int size = queue.size()，然后 for (int i = 0; i < size; i++) 精确出队这么多个。这样既拿到了”层”的概念，又不会把下一层的节点混进来。见 二叉树的右视图 的核心思想一节。

二、收集路径必须用「全局数组 + 回溯」

路径总和 II 这类题（收集所有从根到目标节点的路径），返回值方案会非常难写，因为要返回的不是一个数，而是多条路径的集合。标准做法是：

关键点为什么
存快照 new ArrayList<>(path)直接存 path 会让所有结果指向同一个数组，最后全变成最后一条路径
回溯 path.remove(...)递归返回后要把这一层加的节点删掉，否则兄弟分支会带上它

「存快照」是本题最高频的 bug

不加new ArrayList<> 的话，代码能跑完、结果数组数量也对，但打印出来每一条都是最后那条路径。这类 bug 编译器和测试都可能不报错（如果只有一条路径），务必手动检查。

三、「后序 + 返回贡献值」是树 DP 的入门范式

二叉树中的最大路径和 是本主题唯一的困难题，但它代表的范式值得单独讲：这个递归函数既返回一个值，又更新一个全局变量。

为什么”返回值”和”全局答案”必须是两个不同的量

回到父节点的路径只能选一边（一条从根到叶的路径不能分叉），所以返回 max(left, right) + val；但以当前节点为最高点的路径可以同时用左右两边，所以结算时用 left + val + right。 这两个量不同，正是本题的全部难点。见该篇的核心思想一节。

四、BST 的性质可以白拿

二叉搜索树中第 K 小的元素 只需要中序遍历（BST 的中序必然是有序的），数到第 K 个就停。它看起来太简单，但用来说明一件事：

“当题目给了 BST 这个前提，就要主动想到 BST 的性质”——中序有序、左右子树大小关系、可以按值比较而不是按整棵树比较。

很多树题给了 BST 前提却还傻乎乎地做普通 DFS，就浪费了这个前提。见该篇的思路一节。

五、从前序+中序构造的”边界定位”

从前序与中序遍历序列构造二叉树 是本主题最经典的一道，核心是用两个序列互相切分：

为什么要用哈希表

不用哈希表时，找根在中序里的位置是 O(n)，每层递归都这样，整体退化到 O(n²)。用 HashMap 预先存好”值→下标”，每层定位 O(1)，整体 O(n)。见该篇的关键细节一节。
