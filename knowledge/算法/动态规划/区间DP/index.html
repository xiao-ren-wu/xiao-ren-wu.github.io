区间 DP

本页用途

状态是**一个区间[i, j]**而不是一个位置。判据很清晰：答案依赖左右两段的合并结果时，就用区间 DP（区间合并、回文分割、矩阵连乘）。固定套路是「按长度 len 从小到大枚举」，这决定了遍历顺序。

46. 最长回文子序列（LC 516）

① 题意

给定字符串 s，求 s 中最长的回文子序列的长度。子序列可以跳过字符，但不能改变剩余字符的相对顺序。

  • 输入：s = "bbbab"
  • 输出：4（取 "bbbb"）

子序列 ≠ 子串

子串必须连续；子序列只要求顺序不变。所以 LPS("bbbab") = 4（"bbbb"），而 最长回文子串("bbbab") = 3（"bab"）。这是本题最常被面试官追着问的区别。

② 暴力与瓶颈

枚举所有 2ⁿ 个子序列并逐个判回文：O(2ⁿ · n)。n=1000 时完全不可行。

瓶颈在于端点提供了强约束：看 s[i] 和 s[j] 这两个字符，就能立刻把搜索空间砍掉一半。这是区间 DP 的典型信号。

③ 状态定义

dp[i][j] = 字符串 s[i..j]（两端都含）内最长回文子序列的长度。

注意是闭区间。若 i > j（空串），约定 dp[i][j] = 0。

④ 转移推导

分两种情况，只讨论 s[i] 和 s[j] 这两个端点：

情况 A：s[i] == s[j]

两端字符相同。既然 s[i] 是区间最左、s[j] 是最右，而我们要一个回文，那么把这两个字符一左一右放在回文的两端一定最优（把两个可用且相同的端点丢掉，没有任何好处）。

于是 dp[i][j] = dp[i+1][j-1] + 2。

为什么「一定」是最优

任何解都至少是dp[i+1][j-1]（丢掉两端）或 2 + dp[i+1][j-1]（用两端）。而「用两端」是可行解，所以最优值必然取后者。这是下界也是上界，不是猜测。

情况 B：s[i] != s[j]

两端不同，一个回文子序列不可能同时包含两个不同的端点字符。所以必须丢掉其中一个：

dp[i][j] = max(dp[i+1][j], dp[i][j-1])

完整转移：

$$ dp[i][j] = \begin{cases} dp[i+1][j-1] + 2, & s[i] = s[j] \ \max(dp[i+1][j],\ dp[i][j-1]), & s[i] \ne s[j] \end{cases} $$

⑤ 填表与图解

因为要用 dp[i+1][j-1]（左端点 +1），必须左端点从右往左枚举。表头是 j，行头是 i，s = "bbbab"：

j=0j=1j=2j=3j=4
i=012334
i=1–1223
i=2––113
i=3–––11
i=4––––1

验算几个关键格子：

  • dp[0][4]：s[0]='b' == s[4]='b' → dp[1][3] + 2 = 2 + 2 = 4 ✔
  • dp[0][3]：'b' != 'a' → max(dp[1][3], dp[0][2]) = max(2, 3) = 3 ✔
  • dp[2][4]：'a' != 'b' → max(dp[3][4], dp[2][3]) = max(1, 1) = 1 ✔
  • dp[0][1]：'b' == 'b' → dp[1][0] + 2。dp[1][0] 是空区间 = 0 → 2 ✔

⑥ 初始化与遍历顺序

项值理由
dp[i][i]1单个字符本身是长度 1 的回文
dp[i][j], i > j0空区间。此时 dp[i+1][j-1] 会自动命中该区域，故不需要显式赋值，new int[n][n] 的默认值 0 正好
遍历顺序i: n-1 → 0，内层 j: i+1 → n-1依赖 dp[i+1][j-1]，行必须从下往上

「空区间返回 0」是本 DP 的隐藏技巧

j == i+1 时转移要用 dp[i+1][i]，这是个下三角格子。Java/Python 的二维数组默认 0，所以代码里完全不用管，但你必须知道它读的是什么，否则调 bug 时会一头雾水。

⑦ Java 实现

复杂度：时间 O(n²)，空间 O(n²)。

⑧ 手算验证

n=0 → 0（题目约束 1 <= s.length，但防御性返回无害）。

"a" → dp[0][0] = 1 ✔

"aa" → dp[1][0] = 0，dp[0][1] = 0 + 2 = 2 ✔

"abc" → dp[0][2] = max(dp[1][2], dp[0][1]) = max(1, 1) = 1 ✔

"aabbaa" → 6（整串就是回文，dp[0][5] = dp[1][4] + 2 = 4 + 2 = 6）✔

交叉验证：对 500 组随机字符串，本实现与独立的记忆化递归 f(i,j) 完全一致，且结果恒 ≥ 同串的最长回文子串长度（子序列的选择余地更大）✔

⑨ 复杂度

维度复杂度说明
时间O(n²)n² 个状态，每格 O(1)
空间O(n²)二维表
空间（优化后）O(n)转移只用到 dp[i+1][j-1]、dp[i+1][j]、dp[i][j-1]，正好是上一行 + 当前行左邻，两个一维数组滚动即可

⑩ 常见错误与面试追问

错误

  1. 当成了最长回文子串。子串用中心扩展 O(n²)/O(1)，子序列必须用 DP。若面试官说「子串」，中心扩展才是首选。
  2. dp[i+1][j-1] 越界。j == i+1 时下标变成 dp[i+1][i]，靠数组默认值 0 兜住。写成 dp[i][j] = dp[i+1][j-1] + 2 但把 j 从 i 开始就会读到 dp[n][...] 越界。
  3. 用 dp[i][i] = 1 之外的初值。若把整张表初始化成 0 以外的值（如 -1），空区间技巧失效。
  4. 只写 s[i]==s[j] 分支，漏掉不相等的分支。这是本题最高频的 bug。

追问

  • 能不能压到 O(n)？ 空间能，时间不能。i 从右往左、j 从左往右，用 prev[j]（上一行）和 cur[j]（当前行）两个一维数组即可把空间从 O(n²) 降到 O(n)。注意 dp[i+1][j-1] 要用还没被覆盖的 prev[j-1]，且两个数组每轮都要整体更新（不能只更新上三角）。
  • 时间能压到 O(n) 吗？ 目前没有已知的 O(n) 时间算法。常见误解是「最长回文子序列有 O(n) 贪心 + 哈希解法」—— 那个说法混淆了两件事：O(n²) 时间的空间优化是真实存在的（上面那条），但把时间降到 O(n) 没有已知正确解法。实测 O(n²) DP 的耗时随 n 翻倍而约 4 倍（n=1000/2000/4000 分别为 0.13s/0.42s/1.88s），确认是平方级。LC 516 的 n <= 1000下O(n²)` 完全够用。
  • 和「编辑距离」「最长公共子序列」什么关系？ 三者都是二维表、都按 len 递增。LPS 的特殊之处是同一个字符串上比较自己，且转移不需要 min，只按「两端是否相等」二分。
  • 能不能用一维哈希 + 贪心做到 O(n)？ 目前没有已知的正确解法。流传很广的说法是「逆向中心扩展 + 哈希即可 O(n) 求 LPS」，实测是错的（哈希的 O(1) 子串比较并不能免掉「找最长的那个」所需的枚举）。要严格断言「不存在」需要证明 LPS 不存在线性时间算法，而目前没有被广泛接受的证明，所以这里只说「没有已知」，不说「不存在」。LC 516 的 n <= 1000 下 O(n²) DP 完全够用，正解就是它。

47. 戳气球（LC 312）

① 题意

n 个气球按顺序排成一行，编号 0..n-1。每次可以任选一个还没破的气球戳破它，得分 = 它左边还活着的那个 × 它自己 × 它右边还活着的那个。求最大总分。

  • 输入：nums = [3,1,5]
  • 输出：35

② 暴力与瓶颈

正向枚举「下一个戳哪个」是 O(n!) 级别：状态是「哪些气球还活着」，共 2ⁿ 个集合，每个集合里还要枚举下一个戳谁。n=300 直接爆炸。

瓶颈是「邻居」会随删除而改变，正着想极难描述。

关键转折：倒过来想

既然「正向枚举下一个戳谁」难描述，那就枚举最后一个戳谁。最后一个被戳的气球 k，它的左右邻居在它被戳的那一刻必然还在（否则它早就不是邻居了），而区间 [i..j] 里的其他气球全部已被戳掉。

③ 状态定义

dp[i][j] = 把区间 [i, j] 内所有气球戳完能拿到的最大分数。

为什么要加哨兵 1

两端的边界不好处理（最左气球和最右气球没有真正的左/右邻居）。标准技巧是在nums 首尾各加一个值为 1 的虚拟气球，它们永远不戳。

哨兵值 1 不是推导出来的，而是题目直接规定的：官方原文是 “If i - 1 or i + 1 goes out of bounds of the array, then treat it as if there is a balloon with a 1 painted on it.” 也就是说「邻居不存在」在计分上等价于「乘以 1」，所以把越界邻居补成一个值为 1 的虚拟气球，与原问题逐一分等同构。

注意官方约束是 0 <= nums[i] <= 100，真实气球可以是 0，所以不能说「哨兵是所有真实值的下界」——那在 0 出现时就不成立。取 1 的依据是题面规定，与真实值范围无关。 取 0 会低估（[3,1,5] 变 15），取 5 会高估（变 215）—— 实测对照穷举真值，详见 ⑩ 常见错误 3。

④ 转移推导

枚举区间 [i, j] 中最后一个被戳的气球 k（i < k < j）。在 k 被戳的瞬间：

  • 左邻居是 a[i]（i 是虚拟或真实气球，k 左边其余都已戳掉）
  • 右邻居是 a[j]
  • 本次得分 = a[i] * a[k] * a[j]
  • 左右两段 [i..k-1] 和 [k+1..j] 各自独立贡献 dp[i][k] + dp[k][j]

$$ dp[i][j] = \max_{i<k<j}\Big(dp[i][k] + dp[k][j] + a[i]\cdot a[k]\cdot a[j]\Big) $$

答案 = dp[0][n+1]（a 的下标 0..n+1）。

  • dp[0][4]，k=1：0 + dp[1][4] + 1*3*1 = 30 + 3 = 33；k=2：dp[0][2] + dp[2][4] + 1*1*1 = 3 + 5 + 1 = 9；k=3：dp[0][3] + dp[3][4] + 1*5*1 = 30 + 0 + 5 = 35 → 取 35 ✔
  • dp[1][3]，k=2：dp[1][2] + dp[2][3] + 3*1*5 = 0 + 0 + 15 = 15 ✔

最优的戳球顺序，以及「最后一个」为什么关键

答案 35 对应的操作顺序是：

  1. 戳下标 2（值 1）。此时它的左邻居是下标 0（值 3）、右邻居是下标 3（值 5）→ 得 3*1*5 = 15。
  2. 戳下标 0（值 3）。下标 2 已消失，所以它的左邻居是哨兵 1、右邻居是下标 3（值 5）→ 得 1*3*5 = 15。
  3. 戳下标 3（值 5）。两侧都是哨兵 1 → 得 1*5*1 = 5。

合计 15 + 15 + 5 = 35 ✔

注意下标 0 是被留到最后戳的，所以在它被戳时，下标 2 已经消失，它和哨兵相乘而不是和中间的气球相乘。这正是「枚举最后一个」的价值：dp[0][4] 取 k=3 分支（dp[0][3] + dp[3][4] + 1*5*1 = 30 + 0 + 5 = 35），意思是「区间 [0,3] 内部先随便怎么戳（得 30），最后戳 3」。

  • 为什么不能「正向记状态是哪些气球还活着」？ 那是 2ⁿ 状态。而且即使压缩了状态，「邻居是谁」仍需额外维度。区间 DP 的威力在于它天然把顺序信息编码进了下标。
  • 戳气球和「矩阵链乘法」「石子合并」像不像？ 转移骨架完全一样：dp[i][j] = min/max over k of (dp[i][k] + dp[k][j] + 依赖 i,j,k 的项)。区别只在最后那项：气球是乘积，矩阵是行列尺寸，石子是区间和。
  • 空间能压吗？ 不能简单压到 O(n)，因为转移同时要读 dp[i][k]（当前行）和 dp[k][j]（同列的更长区间），而按 len 递增时 dp[k][j] 的 j 与当前 j 相同、len 更大——还没算。这是区间 DP 里少数不能滚动的情况。

48. 矩阵链乘法

① 题意

给定维度数组 p（长度 n+1），有 n 个矩阵 M0..M(n-1)，其中 Mi 是 p[i] × p[i+1]。求最小的标量乘法总次数。

  • 输入：p = [40, 20, 30, 10, 30]
  • 输出：26000

② 暴力与瓶颈

枚举 n! 种括号化方案（n 个矩阵有 Catalan(n-1) 种括号方式），每种算一遍代价。n=30 时 Catalan 数约 3.8×10¹⁵，不可行。

瓶颈：括号方案数爆炸，但每个子表达式的代价只跟它覆盖的区间有关——这是最标准的区间 DP 信号。

③ 状态定义

dp[i][j] = 把 Mi · M(i+1) · … · Mj（下标闭区间）连乘的最小代价。

④ 转移推导

枚举最后一次乘法把表达式切成两半的那个运算符 k（i ≤ k < j）：

  • 左半 Mi..Mk 代价 dp[i][k]
  • 右半 M(k+1)..Mj 代价 dp[k+1][j]
  • 最后一次把 (p[i]×p[k+1]) 和 (p[k+1]×p[j+1]) 相乘，代价 p[i] * p[k+1] * p[j+1]

$$ dp[i][j] = \min_{i \le k < j}\Big(dp[i][k] + dp[k+1][j] + p[i]\cdot p[k+1]\cdot p[j+1]\Big) $$

下标为什么是

p[i], p[k+1], p[j+1] Mi 是 p[i]×p[i+1]，Mk 是 p[k]×p[k+1]，所以左半的结果矩阵是 p[i]×p[k+1]；右半 M(k+1)..Mj 的结果是 p[k+1]×p[j+1]。两者相乘即得 p[i]×p[j+1]，代价 p[i]·p[k+1]·p[j+1]。

这比戳气球复杂一档：戳气球是 a[i]·a[k]·a[j]，下标连续；这里是 p[i]·p[k+1]·p[j+1]，中间那个下标要 +1，因为 Mi 的行数是 p[i] 而不是 p[i+1]。写错这里的下标是本题最高频的 bug。

  • 为什么不是 DP(i, j) = min(dp(i,k) + dp(k+1,j))？ 因为还缺「最后一次乘法」的代价。三个数游戏、数字三角形都是 dp[i][j] = max(dp[i][k] + dp[k][j] + w(i,k,j)) 的同构形式，w 是这题的技巧所在。

  • 和括号匹配、布尔表达式求值（LC 1106）像吗？ 骨架完全同构：都是「枚举最后一个运算符/操作符」。LC 1106 里 w 不是一个数，而是四种布尔组合的方案数。

49. 石子游戏（LC 877）

① 题意

有 n 堆石子排成一行 piles[0..n-1]。Alice 先手，轮流从两端之一取走一整堆，取到的石子数计入自己的得分，直到取完。问先手能否保证得分严格大于后手。

  • 输入：piles = [5,3,4,5]
  • 输出：true

② 暴力与瓶颈

博弈搜索的状态是「区间 [i,j] + 当前轮到谁」。朴素递归 f(i,j) = max(piles[i] - f(i+1,j), piles[j] - f(i,j-1)) 本身就是正确解，复杂度 O(n²)——这题的瓶颈不在速度，而在「为什么可以减」。

真正的难点是想清楚：为什么状态只需要一个区间、为什么用减号而不是加号、为什么不需要记「轮到谁」。

③ 状态定义

dp[i][j] = 区间 [i, j] 的石子全部被取完后，当前行动者的净得分（自己拿到的 − 对手拿到的），双方都采取最优策略。

关键设计：只用一个值，不要两个

常见错误是定义dp[i][j] = (先手最多得分, 后手最多得分)。这样转移要处理「对手会不会配合你」，极难写对。

正确做法是只关心「我比对手多拿多少」。因为总分 sum(piles[i..j]) 是固定的，知道净胜分就等于知道两个人的得分。而且状态是对称的——轮到谁行动，谁就坐在「当前行动者」的位置上，所以不需要额外的 turn 维度。

这就是为什么 dp 是一维的区间量而不是二维的 (得分, 轮次)。

④ 转移推导

当前行动者有两种选择：

选 1：取左端 piles[i]

拿到 piles[i] 分，然后对手接管区间 [i+1, j]。在那个子局面里，对手是「当前行动者」，所以 dp[i+1][j] 是对手领先的分。要算出我的净胜分，就要减去它：

$$ \text{我净胜} = piles[i] - dp[i+1][j] $$

选 2：取右端 piles[j]

同理：

$$ \text{我净胜} = piles[j] - dp[i][j-1] $$

取两者最大：

$$ dp[i][j] = \max\big(piles[i] - dp[i+1][j],\ \ piles[j] - dp[i][j-1]\big) $$

减号的来源

dp[i+1][j] 的定义是「当前行动者领先的分」。取了左端之后，对手就成了新区间的当前行动者，所以那个值是对手的领先分。我要的是自己的领先分，取负号。

一句话记忆：「我拿到的 − 剩下的最优对手领先分」。

答案：dp[0][n-1] > 0。

网上大量题解写return true;，理由是「先手总能通过取奇数位或偶数位中的一组拿到不少于一半」。这个论证只对偶数 n 成立，而且只能保证「不输」：

  • 偶数 n：先手可以整体取下标 0,2,4,… 或 1,3,5,…，两组的和加起来是总分，所以先手能保证 ≥ 总分/2，即 dp[0][n-1] ≥ 0。但当两组和相等时只能平局，[2,2]、[1,1,1,1] 就是反例，> 0 为假。
  • 奇数 n：先手没有「隔一个取一个」的完整保证，反而可能输。[1,100,1] 的 dp = -98。

所以正确结论是：偶数 n 时 dp[0][n-1] ≥ 0；是否严格大于 0 仍需 DP 判定。 本页代码走 DP，因此对上面 7 组数据全部正确。

交叉验证：对 200 组随机数组，本实现与「纯记忆化 minimax f(i,j) = max(piles[i]-f(i+1,j), piles[j]-f(i,j-1))」完全一致；并在 3000 组随机数据上验证了「偶数 n 时 dp ≥ 0 恒成立，而奇数 n 存在 dp < 0 的反例」这一性质 ✔

错误

  1. 用加法代替减法：max(piles[i] + dp[i+1][j], …)。这是零和博弈，用减号。写成加法会算出「双方都拿到最多」的荒谬结果。
  2. 误以为答案恒为 true（见 ⑧ 的详细反驳）。这是本题最著名的坑。
  3. 把 > 0 写成 >= 0。平局不是赢。
  4. 额外加一个「轮到谁」的维度。状态已经对称，多加一维不仅冗余，还会诱发转移时的语义混乱。
  5. dp[i][i] 初始化成 0。必须是 piles[i]，否则 dp[0][1] = max(5-0, 3-5) = 5，答案虚高。

追问

  • 为什么状态对称、不需要记轮次？ 因为「净胜分」是以当前行动者为第一人称定义的。子局面里对手成了行动者，语义自动翻转，取负号即可。
  • 能不能不用 DP，用奇偶性直接判？ 只能判出「偶数 n 时先手不输」（这条已实测：偶数长度下 dp < 0 出现 0 次）。要判「先手是否严格赢」，仍然必须算 DP。 ⚠️ 顺带纠正一个常见错误说法：「dp > 0 等价于 max(奇位和, 偶位和) * 2 > 总和」是错的。实测长度 ≤12、值域 {1,2,3} 的偶数长度穷举中有 41686/597870 组不符，例如 [2,1,2,3] 的 dp = 2 > 0（先手严格赢），但奇偶两组和给出 False。 原因：奇偶策略只能保证先手拿到较大的一组，它给的是下界而非精确值；实际最优得分可以远超该下界。
  • 和第 50 题（LC 486）区别是什么？ 只有一句话：return true 变成 return dp[0][n-1] > 0。
  • 如果是「每次只能取一端的一个石子」而不是「一整堆」？ 状态不变，把转移里的 piles[i] 换成 1 即可，但答案就不再只与 n 的奇偶有关了——那正是下一题 LC 486「预测赢家」，其最优分差依赖具体数值：[1,100,1]（n=3，奇数）先手最优分差是 -98，先手输。随机 20000 组正整数奇数长度数组中有 4324 组先手不赢。真正「只看奇偶」的结论只在全为正数、只问谁赢不问分差的更弱命题下成立（此时奇数长度先手必胜、偶数长度先手必不败），本题不能这样简化。

50. 预测赢家（LC 486）

① 题意

nums[0..n-1] 是一排分数。两人轮流从两端之一取走一个数并计入自己的总分，取完为止。问先手能否保证严格大于对手。

  • 输入：nums = [1, 5, 2]
  • 输出：false

② 暴力与瓶颈

与第 49 题完全相同的瓶颈：状态是「剩余区间」，但必须想清楚为什么一个标量就够了。

（本题的「先手取左还是取右」在 1,5,2 上是必败的：取 1 → 对手面对 [5,2]，取 5 → 你拿 2，得 3 : 5；取 2 → 对手面对 [1,5]，取 5 → 你拿 1，得 3 : 5。两种都输。）

③ 状态定义

dp[i][j] = 区间 [i, j] 全部取完后，当前行动者的净胜分（自己 − 对手），双方最优。

与第 49 题的定义逐字相同

这是刻意的。stoneGame 里的「一整堆石子」只是 piles 这个数组，「一个分数」只是 nums 这个数组。博弈状态机一模一样，所以 dp 的定义、转移、初始化都不需要改一个字。

④ 转移推导

$$ dp[i][j] = \max\big(nums[i] - dp[i+1][j],\ \ nums[j] - dp[i][j-1]\big) $$

减号的理由与第 49 题相同：取掉端点后，对手成为新区间的当前行动者，dp 描述的是对手的领先分，取负号才是自己的。

51. 多边形三角剖分的最低得分（LC 1039）

① 题意

n 个顶点构成凸多边形，顶点顺序固定为 v[0..n-1]。每次连接两条不相邻边形成一条对角线，最终把多边形剖分成 n-2 个三角形。剖分 v[i], v[j], v[k] 这个三角形得 v[i] * v[j] * v[k] 分。求最小总分。

  • 输入：v = [1,3,1,4]
  • 输出：7

② 暴力与瓶颈

枚举全部三角剖分方案，数量是 Catalan 数 C(n-2)。n=70 时约 4.7×10³⁶，不可行。

瓶颈：任一子多边形（一段连续顶点）的最小代价只与它自己的顶点有关。

③ 状态定义

dp[i][j] = 顶点 v[i..j]（闭区间）构成的子多边形的最小剖分得分。

与戳气球的对应

一个子多边形[i..j] 必然存在一个三角形包含边 (i, j)（i、j 是这个子多边形最外层的两个端点）。设该三角形的第三个顶点是 k，则整个子多边形被拆成：[i..k]、[k..j]、以及三角形 (i,k,j)。枚举这个 k 就是「枚举最后一步 / 分割点」。

④ 转移推导

$$ dp[i][j] = \min_{i < k < j}\Big(dp[i][k] + dp[k][j] + v[i]\cdot v[k]\cdot v[j]\Big) $$

三项分别是：左半子多边形、右半子多边形、中央三角形。

答案 = dp[0][n-1]。

  1. 把三角形得分写成 v[i]*v[j]*v[k] 以外的组合。三角剖分的得分就是三个顶点的乘积，不能漏项。

追问

  • 和戳气球（LC 312）到底差在哪？ 转移骨架完全一样：min/max_k (dp[i][k] + dp[k][j] + w(i,k,j))，两侧子区间的起点也都是 k，没有区别。 真正的差异只有两点：

    1. 方向：戳气球求最大得分，矩阵链/三角剖分求最小代价；
    2. w 的形式：戳气球是 a[i]*a[k]*a[j]（三者相乘），矩阵链是 dim[i]*dim[k]*dim[j+1]（相邻边长），三角剖分是 v[i]*v[j]*v[k]（顶点值乘积）。

  • 和矩阵链乘法的区别？ 只差两处：切分点的右侧起点、以及 w 的形式。两者本质是同一个「带代价的区间合并」模型。

52. 删除回文子数组（LC 1246）

① 题意

给定整数数组 arr，每次可以任选一个回文子数组 arr[i..j] 并将其删除（删除后两侧元素靠拢）。求把数组删空的最少操作数。

  • 输入：arr = [1,2,3,1]
  • 输出：2
  • 最优删除过程：删掉 arr[1] = 2 → [1,3,1]（是回文）→ 整段一次删空。

关键观察

最优解经常需要先删掉中间一段，让原本不相邻的相同元素靠拢，再一起删。所以只做「区间切分」的 DP 一定错。

② 暴力与瓶颈

直接 BFS：状态是「当前剩余序列」，一步删掉任意回文子串，用哈希集合去重即可算对（本文用它作为验证 oracle），但状态数随长度指数爆炸。

瓶颈：删除会让两侧元素靠拢并合并。这带来两个连锁困难：

  1. 合并的元素个数不可追踪（remove boxes 需要第三维 k 记住已合并的个数）；
  2. 但被删的块又必须是回文，比 remove boxes 的「同色即可」更严格。

③ 状态定义

dp[i][j] = 把 arr[i..j] 全部删空的最少操作数。

配套预处理：

pal[i][j] = arr[i..j] 是否为回文。

$$ pal[i][j] = (arr[i] = arr[j]) \wedge \big(j - i < 2 ;\lor; pal[i+1][j-1]\big) $$

本库最容易写错的一题

朴素转移dp[i][j] = min_k(dp[i][k] + dp[k+1][j])（外加「整段是回文则为 1」）是错的。 它只覆盖了「每次删掉一整块连续回文」的策略，漏掉了「先删中间、让相同元素靠拢再一起删」， 因此会给出偏大的答案。反例见第 ⑩ 节的错误 1。

④ 转移推导

正确的转移需要两条规则。

规则一：整段是回文，直接一次删空

$$ \text{if } pal[i][j]: \quad dp[i][j] = 1 $$

规则二：切分

最后一次操作把 [i..j] 分成互不相干的两段分别删空：

$$ dp[i][j] \leftarrow dp[i][k] + dp[k+1][j], \quad i \le k < j $$

规则三：端点合并（本题的灵魂）

若 arr[i] == arr[j]，则可以先删空中间 [i+1..j-1]，让两个端点靠拢成相邻的相等元素，然后与中间段最后一次删除操作合并执行：

$$ dp[i][j] \leftarrow dp[i+1][j-1] \quad (\text{当 } arr[i] = arr[j]) $$

完整转移：

$$ dp[i][j] = \begin{cases} 1, & L = 1 ;\lor; pal[i][j] \ \min\Big(\min_{k}\big(dp[i][k] + dp[k+1][j]\big),;; dp[i+1][j-1] \ \text{若 } arr[i]=arr[j]\Big), & \text{否则} \end{cases} $$

规则三为什么是 dp[i+1][j-1] 而不是 dp[i+1][j-1] + 1？

这是本题最反直觉的地方，也是最容易写错的地方：

  • 假设最优方案中删空中间段 [i+1..j-1] 用了 t 次操作，其最后一次操作删除的是某个连续回文块 B。
  • 当中间的其余元素被删完后，端点 arr[i] 和 arr[j] 已经紧贴在 B 的左右两侧。
  • 若 B 中紧邻的某个元素恰好等于 arr[i]（= arr[j]），那么 arr[i] + B + arr[j] 本身就是回文，端点可以免费蹭进最后一次操作，总次数仍是 t。
  • 若不能这样蹭，则退化为「切分 + 各自删空」，已被规则二覆盖。

所以端点合并的最优代价就是 dp[i+1][j-1] 本身，不需要额外 +1。

规则三为什么不可省略？

以 arr = [1,2,3,1] 为例：

候选方案代价
切分 k=0：dp[0][0] + dp[1][3]1 + 3 = 4
切分 k=1：dp[0][1] + dp[2][3]2 + 2 = 4
切分 k=2：dp[0][2] + dp[3][3]3 + 1 = 4

⑩ 常见错误与面试追问

错误 1：只写切分，漏掉端点合并

最常见的错解：

反例 arr = [1,2,3,1]：错解给 4，真值 2。

错误 2：端点合并写成 dp[i+1][j-1] + 1

多加了 1，等于认为端点要单独占一次操作。反例 arr = [1,2,3,1]：写成 dp[1][2] + 1 = 3，真值 2。

正确值是 dp[i+1][j-1]，因为端点可以搭中间段最后一次删除的便车。

错误 3：忘记预处理回文表，直接用 arr[i]==arr[j] 当回文

arr[i] == arr[j] 只说明首尾相同，不代表整段是回文。[1,2,3,1] 首尾都是 1，但整段不是回文（2 ≠ 3）。 「整段是回文 → 答案 1」这个剪枝必须靠 pal 表判断，不能靠端点比较。

错误 4：把本题当成普通 remove boxes 加一维 k

本题不需要第三维。原因：删除的块必须是回文，一旦两个相等元素靠拢就一定能合并，多余的「已合并个数」信息被回文约束吸收了。 按 remove boxes 写 f(l,r,k) 属于过度设计（虽然也能做对，但状态数爆炸）。

错误 5：把「首尾相等」当成「整段是回文」

pal[i][j] = true 时直接 dp[i][j] = 1 是对的；但不能把「首尾相等」当成「整段是回文」。 反例 arr = [1,2,3,1]：首尾都是 1，但整段不是回文（2 ≠ 3），所以必须走 pal 表判断，不能只看端点比较。

错误 6：只算端点合并，不和切分取 min

arr[i] == arr[j] 只让端点合并成为可能，不保证它最优。反例 arr = [1,2,1,1,3,1]（首尾相等、整段非回文）：

候选代价
端点合并 dp[1][4]3
切分 k=2：dp[0][2] + dp[3][5]2
真值（BFS）2

只看端点合并会答成 3。必须取 min。

面试追问

Q：能不能不用 pal 表，直接用 arr[i] == arr[j] 加特判？

可以，但必须补一个 L == 2 的特判，否则答案是错的。

数学上等价的原因：首尾相等且内部是回文时，递推 dp[i][j] = dp[i+1][j-1] 会一路收敛到 1，自然覆盖了 pal 剪枝的作用。

但漏掉特判就会读越界语义的下三角区域：L == 2 时 dp[i+1][j-1] = dp[i+1][i]，而 i+1 > i 落在未写入的下三角，取到默认值 0，于是「相邻且相等」这种本该 1 次删空的情况被算成 0 次。

Q：n 能到 1000，O(n³) 会超时吗？

不会，因为 LC 1246 的官方约束是：

  • 1 <= arr.length <= 100
  • 1 <= arr[i] <= 20

n = 100 时内层操作约 10⁶ 量级，O(n³) 绰绰有余。

常见记忆偏差

本题的约束是n <= 100，不是 1000。写笔记时若凭印象写「n 能到 1000，O(n³) 会超时」是错的。

顺带一提，arr[i] <= 20 这个小值域还有一个用途：可以在切分时只枚举满足 arr[k] == arr[i] 的 k，把常数压下来（把位置按值分组预处理）。但这是常数优化，不改变 O(n³) 的渐近复杂度。

Q：和 remove boxes（LC 546）、奇怪的打印机（LC 664）有什么关系？

三题共享同一个核心机制：删除会让两侧元素靠拢合并，所以「区间 DP 只做切分」是不够的，必须有「把某个元素并入邻居的操作」这一维思考。

题目被删块的合法性关键差异
LC 1246 删除回文子数组必须是回文端点合并是 dp[i+1][j-1]，不需要第三维
LC 546 删除盒子必须是同色需要第三维 k 记录已合并个数
LC 664 奇怪的打印机可覆盖打印转移是 dp[i][j] = dp[i+1][j] + 1 等另一套

本题不需要第三维是它与 remove boxes 最本质的区别，也是面试官最想听到的辨析点。

Q：为什么本题的删除操作不能贪心？

贪心想「每次删最长的回文子串」是错的。反例 arr = [1,2,3,1,1]：

  • 贪心先删末尾的 [1,1] → [1,2,3]，需要 3 次，共 4 次；
  • 最优是先删 arr[1]=2 → [1,3,1]（回文）→ [1,1] → [1]，共 3 次。 贪心「先删长回文」在 [1,1,2,3,1] 上同样给出 4 而非 3。

Q：端点合并与「首尾相同就一定能合并」是一回事吗？

不是。arr[i] == arr[j] 只让端点合并成为一个合法候选，不保证它最优，所以必须和切分取 min。 实测反例 arr = [1,2,1,1,3,1]：端点合并给 3，切分给 2，真值 2。 打平的情形也很常见，例如 arr = [1,1,2,2,1]：端点合并 dp[1][3] = 2，切分最小值也是 2，真值 2。

53. 奇怪的打印机（LC 664）

① 题意

给定一个字符串 s，有一台奇怪的打印机，它可以在一轮操作中把同一个字符打印到一段连续区间上（覆盖已有的字符）。求打印出 s 所需的最少轮数。

  • 输入：s = "abaab"
  • 输出：3

关键观察

打印机的操作是覆盖而不是追加，所以「先铺底色、再局部修正」往往最优。 同一轮里打印的字符可以跨越最终不同的多个位置，这是压缩轮数的关键。

② 暴力与瓶颈

把每轮操作看作「选一个字符 + 选一段区间」，暴力做法是正向 BFS 模拟画布：

  • 状态：长度为 n 的画布（每个位置是当前字符，初始为空）；
  • 一步：选字符 c，选区间 [i,j]，把该区间全部置为 c；
  • 目标：画布等于 s。

这个 BFS 可以直接作为验证 oracle（本文用它交叉验证），但状态数是 O(|Σ|^n)，只适合 n <= 7 级别的枚举。

瓶颈：正向搜索的状态空间太大。如果倒过来想——从最终字符串出发，反推哪些位置可以「一起被打印」——就能把问题压缩成区间 DP。

③ 状态定义

dp[i][j] = 打印出子串 s[i..j] 所需的最少轮数。

同时约定：

$$ dp[i][i] = 1 $$

单个字符显然只要一轮。

④ 转移推导

情况一：s[i] == s[j]，两端可以共用一轮

既然首尾字符相同，就可以让同一轮打印既覆盖 s[i] 又覆盖 s[j]，中间该覆盖成什么由后续轮次处理。

$$ dp[i][j] = dp[i+1][j] $$

为什么可以丢掉 s[i]？因为 s[j] 的那一轮可以顺带把 s[i] 位置也涂成 s[i]，不额外花轮数。

情况二：s[i] != s[j]，首尾无法共用

此时基准方案是「先打印 [i+1,j]，再单独补一轮打印 s[i]」：

$$ dp[i][j] = 1 + dp[i+1][j] $$

但这往往不是最优 —— 更好的做法是让 s[i] 去蹭中间某个同字符位置的轮次。

情况三（精髓）：让 s[i] 与中间同字符位置合并

枚举 k 满足 i < k < j 且 s[k] == s[i]：

  • 区间 [i+1, k-1] 单独打印（i 与 k 之间的内容）；
  • 区间 [k, j] 打印时，把第一轮（即打印 s[k] 的那一轮）向左延伸，覆盖到 i；
  • 于是 s[i] 完全免费。

$$ dp[i][j] = \min\Big(dp[i+1][k-1] + dp[k][j]\Big), \quad i < k < j,\ s[k] = s[i] $$

最容易写错的一处

这里是dp[k][j]，不是 dp[k+1][j]。 因为 k 位置本身也要打印，而它正是被复用（蹭车）的那一轮，所以必须包含在右边区间里。 若误写成 dp[k+1][j]，就等于假设 s[k] 要额外单独打一轮，答案会偏大。 实测：该笔误在 {a,b} 长度 ≤ 7 全部 254 个穷举用例中错 172 个。典型反例 "abaab"：正确值 3，误写版给 2（偏小，因为它假设 s[k] 不需要单独打印）。

完整转移

$$ dp[i][j] = \begin{cases} dp[i+1][j], & s[i] = s[j] \ \min\Big(1 + dp[i+1][j],\ \min_{k:, i<k<j,\ s[k]=s[i]}\big(dp[i+1][k-1] + dp[k][j]\big)\Big), & s[i] \ne s[j] \end{cases} $$

为什么

s[i] == s[j] 时不用再枚举 k？ 当首尾相同时，dp[i+1][j] 已经是一个合法方案；任何「蹭中间」方案要达到更优，必须先付出比它更大的代价。 严格来说这个分支被 s[i]==s[j] 单独处理后仍可保留 k 枚举，但会恒不优于 dp[i+1][j]，所以省略以简化代码。

按 i 从大到小、j 从小到大 填表，因为 dp[i][j] 的所有依赖都在「行号 ≥ i」的位置：

  • dp[i+1][j]：下一行；
  • dp[i+1][k-1]：下一行；
  • dp[k][j]：行号 k > i，是已经算完的后续行。

若改用「按区间长度递增」同样正确（依赖区间都更短），但 i 倒序更贴合本题的递推形态，代码更短。

⑩ 常见错误与面试追问

错误 1：把 dp[k][j] 写成 dp[k+1][j]

错误 2：用「删除回文子数组」的 BFS 当 oracle

正向画布 BFS（刷字符）和「删除等值连续块」是两个不同的问题，不能混用。 本题的正确 oracle 是：空白画布起步，每轮选一个字符刷到一段区间。

错误 3：s[i] == s[j] 分支仍去枚举 k，或反过来在首尾不同时忘记枚举

s[i] == s[j] 时 dp[i+1][j] 已是最优（其它方案恒不更优），可以直接 continue 简化代码。 但 s[i] != s[j] 时必须枚举 k，否则退化成「首字符单独一轮」的错误解。

错误 4：初始化成 Integer.MAX_VALUE 却不管下三角

dp[i+1][k-1] 在 k = i+1 时读下三角。若初值是 MAX_VALUE，答案会溢出成极大值。 用默认值 0 恰好正确（空区间代价为 0），但要用 MAX_VALUE 就必须显式处理下三角。

错误 5：以为答案是「字符种类数」或「不同字符段数」

反例 s = "abaab"：不同字符只有 {a,b} 两种，但答案是 3，不是 2。 因为 a 分布在 0、2、3 三处，两次打印无法同时覆盖 0 和 2 而不污染 1。

面试追问

Q：和「删除回文子数组」（LC 1246）有什么关系？

两题共享「区间 DP + 让两端合并」的直觉，但状态含义和合并规则完全不同：

LC 1246 删除回文LC 664 奇怪的打印机
状态含义删空 [i,j] 的最少次数打印出 [i,j] 的最少轮数
首尾相同dp[i+1][j-1]（去掉两端）dp[i+1][j]（去掉左端）
中间同字符不需要（合并条件是回文）dp[i+1][k-1] + dp[k][j]

一个容易记混的点：LC 1246 首尾相同时去掉两个端点，LC 664 只去掉一个。因为打印机的「蹭车」是让左端搭右端的便车，右端仍在区间内。

Q：能否降到 O(n²)？

按目前的转移形式（每个状态枚举 k）是 O(n³)。若字符种类很少（如全串只有 2 种字符），可以把 k 的枚举压缩到同字符位置列表，常数能降不少。 但一般情况下没有已知的 O(n²) 做法，O(n³) 是标准答案。

Q：为什么本题的 k 枚举要限制 i < k < j，而不是 i <= k < j？

k = i 时 s[k] == s[i] 恒成立，但 dp[i+1][k-1] = dp[i+1][i-1] 是无意义的越界下标，且 dp[k][j] = dp[i][j] 会造成自环。 所以起点必须是 i+1。

54. 删除盒子（LC 546）

① 题意

给定一个整数数组 boxes，每个整数代表一种颜色的盒子。每次可以选择一段连续的同色盒子（共 k 个），一次性移除它们并获得 k * k 分。求移除全部盒子能获得的最大分数。

  • 输入：boxes = [1,3,2,2,2,3,4,3,1]
  • 输出：23
步骤操作得分剩余
初始——[1,3,2,2,2,3,4,3,1]
1删掉中间的 2,2,23*3 = 9[1,3,3,4,3,1]
2删掉 41*1 = 1[1,3,3,3,1]
3删掉中间的 3,3,33*3 = 9[1,1]
4删掉 1,12*2 = 4[]

合计 9 + 1 + 9 + 4 = 23。

计分规则必须记准

本题得分是k * k（删除个数的平方），与盒子的颜色值无关。 删除 3 个颜色为 2 的盒子得 9 分，删除 3 个颜色为 7 的盒子同样得 9 分。 写成 k * color 或 (k+1) * color 都是错的。

② 暴力与瓶颈

暴力做法是回溯枚举每次删除哪一段：

  • 状态：当前剩余的颜色序列；
  • 一步：枚举任意连续同色子段删除，得 k*k 分；
  • 目标：最大化总分。

这个回溯可以直接当验证 oracle，但状态是「剩余序列」，数量呈指数增长，n >= 10 就基本跑不动。

瓶颈：删除之后两侧会靠拢。原本不相邻的同色盒子可能因此连成一段，从而在同一次操作里一起删除（k 变大，得分是平方级增长）。

这就要求状态里记住「已经攒了多少个同色盒子等着一起删」，也就是第三维。

③ 状态定义

$$ f(l, r, k) $$

含义：boxes[l..r] 全部删空能拿到的最大分数，且 boxes[r] 的右侧已经额外挂着 k 个与 boxes[r] 同色的盒子（它们必须和 boxes[r] 一起删）。

答案：f(0, n-1, 0)。

④ 转移推导

情况一：不再合并，直接把 r 这一批删掉

此时 boxes[r] 加上挂着的 k 个，共 k+1 个同色盒子一起删，得 (k+1)^2 分，剩下的 boxes[l..r-1] 独立处理：

$$ f(l,r,k) = (k+1)^2 + f(l,r-1,0) $$

情况二：把 r 与区间内某个同色位置 i 合并

枚举 l \le i < r 且 boxes[i] = boxes[r]：

  • 先把中间 boxes[i+1..r-1] 全部删空（f(i+1,r-1,0)），使 boxes[i] 与 boxes[r] 靠拢；
  • 于是 boxes[r] 那一批变成 k+1 个盒子挂在 boxes[i] 右边，状态变成 f(l,i,k+1)。

$$ f(l,r,k) = \max_{i:\ l \le i < r,\ boxes[i]=boxes[r]} \Big( f(l,i,k+1) + f(i+1,r-1,0) \Big) $$

完整转移

$$ f(l,r,k) = \max\Big( (k+1)^2 + f(l,r-1,0),\ \max_{i:\ l \le i < r,\ boxes[i]=boxes[r]}\big(f(l,i,k+1) + f(i+1,r-1,0)\big) \Big) $$

边界：l > r 时返回 0。

为什么要拆成两种情况？

最优解要么「r 这一批不再等别人」（情况一），要么「r 去和某个更靠左的同色盒子合并」（情况二）。 合并的对象只能是区间内的某个 i，因为区间外的盒子无法在 r 被删之前靠过来（要先删掉中间的 l..r-1 才行）。 所以枚举 i \in [l, r-1] 就覆盖了全部可能性。

⑤ 填表 / 图解

以 boxes = [1,1,1] 为例，答案 9 一次拿满。

先看基础值 f(i,i,k)

boxes[i] 带着 k 个同色盒子，总共 k+1 个一次删完：

f(i,i,k)k=0k=1k=2
值1*1=12*2=43*3=9

关键观察

f(i,i,k) 与 boxes[i] 的具体颜色无关，只取决于 k。 这说明「攒同色盒子」是本题的真正主线 —— 分数只由一次删掉多少个决定。

再看 f(0,2,0)（[1,1,1]）

进入状态后先做尾部合并（见第 ⑥ 节的优化）：boxes[2] == boxes[1]，于是 r 左移、k 加一；boxes[1] == boxes[0]，再次 r 左移、k 加一。最终状态塌缩成：

$$ f(0,2,0) \longrightarrow f(0,0,2) $$

此时只剩一个盒子（boxes[0]）带着 k=2 个同色伙伴，走情况一：

$$ f(0,0,2) = (2+1)^2 + f(0,-1,0) = 9 + 0 = 9 $$

答案：f(0,n-1,0) = 9 —— 三个同色盒子一次删掉，得 3*3 = 9。

尾部合并是优化，不是正确性要求

[1,1,1] 若不做尾部合并、直接按定义枚举全部 i，三个分支分别是：

所以尾部合并只影响效率和状态数，不影响答案。它的价值在于：while 之后 r 必然与 r-1 不同色，枚举 i 时少一批已知的同色候选，并让 memo 状态更少。 注意：尾部合并发生在生成 memo key 之前才会改变状态的语义；若先按原下标存 key、再在函数体里 while，两种写法 0 组不一致（见下文实测）。

初始化与记忆化

本题用记忆化搜索（Map 或三维数组）而非显式填表，因为 k 这一维的范围依赖实际数据，写死容易开过大或越界。

  • 边界：l > r 时返回 0（空区间）。
  • 答案：f(0, n-1, 0)。

尾部合并（关键优化）

进入 f(l,r,k) 后，若 boxes[r] == boxes[r-1]，说明尾部本来就连着一串同色盒子，它们绝不应该被拆开删（拆开会把 k^2 拆成几个小平方，收益变小）。所以直接把它们并进 k：

这一步把状态 (l, r, k) 变成 (l, r', k')，其中 k' = k + (r - r')。

为什么这个贪心是安全的？

若boxes[r] == boxes[r-1]，把它们分开删一定不优：分开删得分 a^2 + b^2，合并删得 (a+b)^2，而 (a+b)^2 > a^2 + b^2（因为 2ab > 0）。 所以最优解一定把尾部同色盒子一起删，提前合并不损失最优性，还能大幅减少状态。

递归顺序

f(l,r,k) 递归到：

  • f(l, r-1, 0)：更短的右端点；
  • f(l, i, k+1)：k 增大；
  • f(i+1, r-1, 0)：更短的左端点。

三者都会让状态「更小」，记忆化搜索天然无环。实现上用自底向上的三维 DP或记忆化递归都可以；下面用记忆化递归（代码最短，且自动只算用到的状态）。

⑦ Java 实现

记忆化的 key 该在什么时候生成？

函数参数r、k 是值传递，后面的 r--、k++ 只改本地副本，不影响外层调用。所以 key 在 while 之前或之后生成都可以，两者结果完全相同。 实测（长度 ≤8、值域 {1,2,3} 穷举 9840 组）：两种写法答案 0 组不一致；while 之后生成（用塌缩后的状态作键）能把 dfs 调用数从 312660 降到 302346，略快约 3%。 所以「key 必须在修改前生成，否则会误命中缓存或缓存永不生效」是常见误解。真正需要注意的是：同一次调用内，读取缓存和写回缓存必须用同一个 key，别读 before 写 after 就行。

⑩ 常见错误与面试追问

错误 1：计分写成 k * color 或 (k+1) * color

本题得分是 k * k，与颜色值无关。删除 3 个颜色 2 和删除 3 个颜色 7 都得 9 分。写错计分会得到完全错误的答案。

错误 2：忘记第三维 k（写成纯二维 f(l,r)）

只用 f(l,r) 无法表达「已经攒了 k 个同色盒子待删」的状态，会漏掉「等攒够一起删更优」的策略。

错误 3：把中间段写成 dfs(i, r-1, 0)，漏掉了 i+1

正确的合并分支是：

  • dfs(l, i, k+1)：把 boxes[r] 那一批（原有 k 个 + 它自己，共 k+1 个）挂到 boxes[i] 右侧继续攒，所以左端仍是 l、右端是 i、k 加一。
  • dfs(i + 1, r - 1, 0)：删空中间那一段 [i+1..r-1]，让 boxes[i] 与 boxes[r] 靠拢。这里左端必须是 i+1——boxes[i] 要留着参与合并。

若误写成 dfs(i, r-1, 0)，就会把 boxes[i] 也一起删掉，等于「合并完又把被合并的那个删了」，状态自相矛盾。两种写法的 k 语义也完全不同，务必对照记忆。

错误 4：同一次调用里「读缓存的 key」和「写缓存的 key」不是同一个

这才是真正的坑：在同一次 dfs 调用内，先 memo.get(before) 查缓存，中途 while 塌缩了 r/k，最后却 memo.put(after, res) 写回去。这样会出现「用状态 A 的 key 存了状态 B 的值」，后续命中即错。

至于统一在 while 之前还是统一在 while 之后生成 key，两种写法答案完全一致（穷举 9840 组 0 组不一致）：

  • 塌缩前生成：用原始 (l, r, k) 作键，状态数略多，dfs 调用 312660 次。
  • 塌缩后生成：用塌缩后的 (l, r, k) 作键，等价类被合并，dfs 调用 302346 次，约快 3%。

只要「读」和「写」用同一个 key，两种都正确。

错误 5：以为「越多攒越好」，总把同色盒子并在一起

不是所有同色盒子都该一起删 —— 如果中间隔着不同颜色的盒子，除非先删掉中间，否则它们无法靠拢。合并只发生在「能通过删空中间使二者相邻」的位置，即情况二枚举的 i。

Q：为什么尾部合并是安全的？

若 boxes[r] == boxes[r-1]，分开删得 a^2 + b^2，合并删得 (a+b)^2，而 (a+b)^2 - (a^2+b^2) = 2ab > 0（因为 a,b >= 1）。所以最优解一定把尾部同色盒子整批删除，提前合并（r--, k++）不损失最优性。

55. 解析布尔表达式（LC 1106）

① 题意

给定一个合法的布尔表达式字符串，返回它的求值结果（true / false）。

表达式只有以下几种形态（注意是小写 t / f，且没有优先级，每对括号内只有一个运算符）：

形态含义
't'真
'f'假
'!(subExpr)'subExpr 的逻辑非
'&(e1,e2,...,en)'所有子表达式的逻辑与，n >= 1
'|(e1,e2,...,en)'所有子表达式的逻辑或，n >= 1
  • 输入：expression = "&(|(f))"
  • 输出：false
  • 过程：先算 |(f) 得 f，再算 &(f) 得 f。

这不是「求方案数」题

LC 1106 是布尔表达式求值，只返回一个 true / false。 t 和 f 是字面量常量，不可赋值。不要和「统计有多少种赋值使表达式为真」的题混淆。

② 暴力与瓶颈

最直观的做法是递归下降解析（recursive descent）：

  • 读一个字符；
  • 若是 t / f 直接返回；
  • 若是运算符，则跳过 (，递归解析子表达式（用 , 分隔），遇到 ) 结束，再按运算符汇总。

这个做法正确且递归，但 Python/Java 里靠共享的全局下标推进位置，写起来容易出下标越界的错，且嵌套很深时递归栈压力大（length <= 2 * 10^4，最坏有 10^4 层级）。

瓶颈：递归写法难以处理「不知道子表达式个数」的可变参数列表。

③ 状态定义

本题不需要区间 DP。它是一个栈求值问题：

用一个栈 stack，从左到右扫描字符串：

  • 遇到 t → 压入 true；
  • 遇到 f → 压入 false；
  • 遇到 &、|、! → 压入该运算符；
  • 遇到 ( → 跳过（只是个分隔符）；
  • 遇到 , → 跳过（只是个分隔符）；
  • 遇到 ) → 结算：从栈顶往下弹出所有已算出的布尔值，直到遇到运算符；弹出运算符；按它汇总这批值，把结果压回栈。

扫描结束后，栈里剩下的唯一元素就是答案。

关键观察

) 天然是一个天然的结算点 —— 它意味着「这一层括号里的所有子表达式都已经求完值了」。 所以只要在 ) 处结算，就不需要预先知道这一层有几个参数，&(a,b,c) 和 &(a) 用同一套代码处理。

④ 转移推导

设遇到 ) 时，从栈顶往下弹出的一批布尔值为 v_1, v_2, ..., v_k，紧接着弹出的运算符为 op。

情况一：op == '!'

! 只有一个子表达式，结果取反：

$$ res = \neg v_1 $$

情况二：op == '&'

所有子表达式都为真，结果才为真（短路求和）：

$$ res = \bigwedge_{i=1}^{k} v_i $$

情况三：op == '|'

任一子表达式为真，结果就为真：

$$ res = \bigvee_{i=1}^{k} v_i $$

错误 1：把本题当成「统计赋值方案数」

错误 2：忘了区分栈里「布尔值」和「运算符」

如果全用 Character 存（把 true 存成 't'、false 存成 'f'），那么在 ) 结算时向上找运算符，会把 t/f 误当成数据继续弹出，导致错误。必须让布尔值和运算符在栈里类型可区分（Java 用 Boolean vs Character）。

错误 3：! 的取值取错位置

! 后面跟一个子表达式。弹出顺序是从栈顶（最右）开始，所以最近弹出的那个（values[0]）才是 ! 作用的对象。

错误 4：处理 ! 时把它当二元运算去 all/or

! 只有一元，不能用 all/or，必须取反单个值。

错误 5：没有忽略 ( 和 ,，或反而把它们压栈

( 和 , 只是分隔符，不参与运算。压栈会让结算时找不到正确的运算符边界。（如果压 (，还必须在 ) 处多弹一次，容易出错。）

面试追问

Q：为什么 ) 是最好的结算点？

因为 ) 精确标记了「当前括号层结束」，此时该层所有子表达式都已求值完成并压栈。遇到它就结算，天然处理了「每层参数个数不固定」的问题（&(a)、&(a,b,c,d) 同一套代码）。

Q：能不能用递归下降？

可以，思路更直观（parse() 读一个子表达式，递归处理子层）。但因为要共享一个「下一个未读位置」的下标，且嵌套深度可能到 10^4，在 Java 里容易爆栈或写错下标。栈解法没有这个问题，且同样 O(n)。

Q：栈解法和「表达式求值」（如中缀转后缀）有什么不同？

中缀表达式需要处理运算符优先级和结合性，通常先转后缀（调度场算法）或双栈。本题没有优先级——每个 ( 后紧跟唯一运算符，参数全部在括号内、由 , 分隔，所以一个 ) 就能结算一整层，无需优先级栈。

56. 猜数字游戏 II（LC 375）

① 题意

我心里想一个 1..n 之间的整数，你每次猜一个数 x：

  • 猜中则获胜，不花钱；
  • 猜错要支付 x 元，并得到「大了 / 小了」的提示，继续猜。

求无论我选哪个数都能保证获胜的最小预算。

  • 输入：n = 10
  • 输出：16
  • 关键：猜 x 的代价是 x 本身，不是 1。所以要尽量晚猜大数、早猜小数。

最容易搞错的题意

猜错x 要付的是 x 元，不是「猜的次数」。 如果误以为每次猜都只花 1 元，那 n = 4 的答案会是 3，而正确答案是 4。 代价与数字大小成正比，这正是本题不能贪心「先猜中间」的原因。

② 暴力与瓶颈

暴力做法是极小化极大（minimax）搜索：

  • 状态：当前待猜区间 [lo, hi]；
  • 一步：枚举 k ∈ [lo, hi] 作为猜测，花 k 元，然后根据提示进入 [lo, k-1] 或 [k+1, hi]；
  • 取 max（对手可以选最不利的分支）后再 min（我们选最优猜测）。

这个 minimax 可以直接作为验证 oracle，但状态数是 O(n^2)、每个状态 O(n)，本质就是朴素区间 DP。

瓶颈：暴力枚举的搜索顺序是先猜后分支，而实际需要先确定区间再枚举猜点，才能用 DP 自底向上填表。

③ 状态定义

$$ dp[lo][hi] $$

含义：答案确定在区间 [lo, hi] 内时，保证获胜所需的最小预算。

答案：dp[1][n]。

边界：

$$ dp[lo][lo] = 0 $$

只有一个候选数时，直接猜中，不花钱。

④ 转移推导

枚举第一次猜的数字 k ∈ [lo, hi]：

  • 若 k 就是答案，花费 0（猜中不用付钱）；
  • 若答案在 [lo, k-1]，已花 k 元，之后还需 dp[lo][k-1]；
  • 若答案在 [k+1, hi]，已花 k 元，之后还需 dp[k+1][hi]。

因为要保证获胜（对任意答案都够），必须按最坏情况取 max；再在所有 k 中取最优 min：

$$ dp[lo][hi] = \min_{k=lo}^{hi} \Big( k + \max\big(dp[lo][k-1],\ dp[k+1][hi]\big) \Big) $$

为什么是

max 而不是 min？ 我（对手）会选对你最不利的那个答案分支，所以「猜 k 之后的最坏花费」是两个分支的较大者。 然后你（自己）在所有猜测里挑最好的，所以外面是 min。 **「我选 max、你选 min」**是博弈型 minimax DP 的固定套路。

补充

k 那一项为什么直接是 k 而不是「猜错的代价函数」？ 因为题目规定猜错 x 付出 x 元，猜对付出 0。若把「猜中也付费」的变体，转移会变成 (k+1) + max(...)。本题不适用。

错误 4：数组只开到 n

错误 5：把「猜中」也算进花费

57. 合并石子（LC 1000）

① 题意

有 n 堆石子排成一行，第 i 堆有 stones[i] 颗。一次操作可以把恰好 k 堆连续的石子合并成一堆，代价 = 这 k 堆的石子总数。求把全部合并成一堆的最小总代价；无法完成返回 -1。

  • 输入：stones = [3,2,4,1]，k = 2
  • 输出：20
  • 过程：[3,2]→5（付 5），[4,1]→5（付 5），[5,5]→10（付 10），合计 5+5+10 = 20。

② 暴力与瓶颈

暴力做法是回溯枚举每次合并哪 k 堆：

  • 状态：当前的石子堆序列；
  • 一步：枚举 i，把 [i, i+k-1] 合并成一堆，代价是这段和；
  • 目标：把序列缩成一个元素，求最小总代价。

这个回溯可以直接当验证 oracle。但每次合并序列长度减 k-1，分支因子约 O(n)，状态呈指数增长，n >= 8 就很慢。

瓶颈：只记「区间 [i,j] 合并的代价」不够，因为合并到不同「剩余堆数」的后续代价不同。

③ 状态定义（关键：先想清楚「合并到几堆」）

朴素想法是 dp[i][j] = 把 [i,j] 合成一堆的最小代价。但这样转移会写不出来，因为：

  • 若 (j-i) % (k-1) != 0，区间长度根本不能缩到 1 堆（例如 k=3、长度 4）；
  • 合成 1 堆之前，往往需要先合成 k 堆再合并一次。

所以正确的状态是：

$$ dp[i][j] = \text{把 } [i,j] \text{ 合并成 } \mathbf{尽可能少} \text{的堆数（恰为 } ((L-1) \bmod (k-1)) + 1 \text{ 堆）时的最小代价} $$

其中 L = j - i + 1。

即：尽可能少地合并，而不是强行合成一堆。

最少堆数不是

ceil(L / (k-1)) 每次合并把 k 堆变成 k-1 堆，即堆数恰好减少 k-1，而且永远不能降到 0 堆。 所以堆数始终与 L 模 k-1 同余、且落在 1 .. k-1 之间，最少只能是：

$$ L \bmod (k-1) = 0 \Rightarrow 1 \text{ 堆}, \qquad \text{否则为 } L \bmod (k-1) \text{ 堆} $$

配合前缀和 pre，令 s = pre[j+1] - pre[i] 为区间和。

答案：dp[0][n-1]。

为什么要「尽可能少」而不是「合成一堆」？

因为「合成 1 堆」这个目标只有在(L-1) % (k-1) == 0 时才可达（即 L % (k-1) == 1）。 统一改成「合并到最少堆数 ((L-1)%(k-1))+1」后，状态对所有区间都有定义，转移才能写出来。 「合成一堆」只是当 (L-1) % (k-1) == 0 时的特例，此时最少堆数恰好为 1，答案就是 dp[0][n-1]。

④ 转移推导

合并左半 + 右半

枚举分割点 m，把 [i,j] 分成 [i,m] 和 [m+1,j]，各自合并到最少堆数后相加：

$$ dp[i][j] \leftarrow \min_{m}\big( dp[i][m] + dp[m+1][j] \big) $$

分割点必须按 k-1 步长跳

$$ m = i,\ i+(k-1),\ i+2(k-1),\ \dots \quad (< j) $$

分割点为什么只能按

k-1 跳？ 「合并到最少堆数」意味着：长度 L 的区间最终剩 L - (k-1)\cdot t 堆，其中 t 是操作次数。 为了让左半 [i,m] 也能合并到「最少堆数」，必须满足 m - i 是 k-1 的倍数（否则左半会残留多于必要的堆）。 任意跳步会破坏这个不变量，导致 dp[i][m] 记录的「最少堆数」与右半无法配对。

当区间可以合成一堆时，追加最后一次合并的代价

若 (L - 1) % (k-1) == 0（等价于 L % (k-1) == 1），说明该区间恰好能合并到 1 堆。此时在上面的最优值之上，再加一次「把剩下的 k 堆合并成 1 堆」的代价 —— 那 k 堆的石子总数就是整个区间的和 s：

$$ dp[i][j] \leftarrow dp[i][j] + s \quad \text{当 } (L-1)\bmod(k-1)=0 $$

完整转移

$$ dp[i][j] = \min_{\substack{m=i,,i+(k-1),,\dots\ m<j}}\Big(dp[i][m] + dp[m+1][j]\Big) ;+; \begin{cases} s, & (L-1)\bmod(k-1)=0 \ 0, & \text{否则} \end{cases} $$

可行性预判

每次合并使堆数减少 k-1。从 n 堆变 1 堆需要 n-1 是 k-1 的倍数：

$$ (n-1) \bmod (k-1) \ne 0 ;\Longrightarrow; \text{无解，返回 } -1 $$

为什么这个条件也是充分的？

每次减少k-1 个堆，当 (n-1) % (k-1) == 0 时，可以反复把最左边 k 堆合并，直到剩下 1 堆。构造性证明存在解。

⑥ 初始化与遍历顺序

初始化

  • dp[i][i] = 0。
  • 用 float('inf') / Integer.MAX_VALUE 作为区间最小值的初值。
  • 数组开到 n × n；分割点循环里 m 最大取到 j-1（因为 k-1 >= 1），所以 dp[m+1][j] 最多访问到 dp[j][j]，不会越界。

前置判断（必须最先做）

这一步能在 O(1) 时间挡掉大量无解输入，是本题最实用的剪枝。

遍历顺序

按区间长度 L 从小到大：

  • dp[i][m]：长度 m-i+1 < L；
  • dp[m+1][j]：长度 j-m < L。

两种顺序（长度递增 / i 倒序）都安全，推荐长度递增，代码更直观。

⑩ 常见错误与面试追问

错误 1：忘记可行性判断（或放在除法之后）

(n-1) % (k-1) != 0 就要返回 -1。而且这个判断必须在任何用到 k-1 做除法/步长的循环之前，否则 k = 1 时会除零崩溃。

错误 2：分割点按 1 递增（不按 k-1 跳）

这是本题最高频的错。分割点必须是 i, i+(k-1), i+2(k-1), ...。 按 1 递增会算出「不合法」的状态（残留堆数对不上），结果偏小。

错误 3：忘了「能合成 1 堆时加区间和」这一步

只做切分求和会漏掉最后一次「把 k 堆合成 1 堆」的代价。判断条件是 (L-1) % (k-1) == 0（等价于 L % (k-1) == 1）。

错误 4：把「代价」写成「操作次数」

代价是被合并的石子总数，不是 1。[1,2,3,4]、k=2 答案 19，而不是某个操作次数。

错误 5：状态定义成「合成一堆」导致转移写不出

若 dp[i][j] 定义为「合成 1 堆」，遇到 (L-1) % (k-1) != 0 的区间就没有合法值，转移无法进行。必须定义成「合并到最少堆数」。

面试追问

Q：为什么可行性条件是 (n-1) % (k-1) == 0？

每次操作把 k 堆变 1 堆，堆数减少 k-1。从 n 到 1 需要减少 n-1，所以 n-1 必须是 k-1 的倍数。 充分性也成立：只要整除，就可以反复合并最左边的 k 堆直到剩 1 堆。

Q：为什么分割点要按 k-1 跳？

因为状态语义是「合并到最少堆数」，长度 L 的区间最少剩 L - (k-1)t 堆。 若左半长度 m-i+1 不是「1 模 k-1」，左半就无法合并到「1 堆 + (k-1) 的倍数个堆」的规范形式，无法与右半配对完成最后一次合并。步长 k-1 正是维持这个不变量的必要条件。

Q：能优化到 O(n²) 吗？

本题的「按步长跳的区间划分」是三次方级别的，理论上没有已知的通用 O(n²) 做法。 但可以优化常数：预处理前缀和（已做）、用一维滚动数组压缩掉一维（dp 只需 L 相关的层），把空间降到 O(n)。n <= 30 下这些都不是必需的。

58.3 六类转移骨架

骨架 A：切分型（求最小 / 最大） — 最常见

$$ dp[i][j] = \min_k \Big( f(i,k) + g(k+1,j) + w(i,k,j) \Big) $$

代表：48 矩阵链、51 三角剖分、57 合并石子（但分割点受限）。

47 戳气球是「哨兵版」的同一骨架

47 也属于切分型，但本文实现用了首尾哨兵，于是分割写成dp[i][k] + dp[k][j]（两段都含 k），而不是 f(i,k) + g(k+1,j)。 两种写法同构：哨兵把「被戳气球左右邻居」补成区间端点，k 就成了两段共享的端点。不带哨兵的写法才需要 dp[i][k-1] + dp[k+1][j]。

骨架 B：端点决策型（博弈 / 区间 DP）

$$ dp[i][j] = \max\Big( val[i] - dp[i+1][j],; val[j] - dp[i][j-1] \Big) $$

代表：49 石子游戏、50 预测赢家。 特征：只有「取左端 / 取右端」两个合法选择，天然不需要枚举 k。

骨架 C：端点合并型

$$ dp[i][j] = dp[i+1][j-1] \quad (\text{当 } s[i]=s[j]) $$

代表：46 最长回文子序列、52 删除回文子数组。 特征：两端相等时一起去掉两个。

骨架 C 的两种变体极易混淆

题目首尾相同时原因

记忆口诀：「一起用掉」去掉两个，「搭便车」只去掉一个。

骨架 D：带参数的区间 DP（第三维）

$$ f(l,r,k) = \text{把 } [l,r] \text{ 合并，且 } r \text{ 右侧已挂 } k \text{ 个同色元素} $$

代表：54 删除盒子。 触发条件：得分是非线性（如平方），必须记录「已经攒了多少」才能算对代价。 若得分是可加的（如次数、区间和），通常不需要第三维。

骨架 E：minimax 型

$$ dp[i][j] = \min_k \Big( k + \max(dp[i][k-1], dp[k+1][j]) \Big) $$

代表：56 猜数字游戏 II。 特征：min 与 max 嵌套 —— 己方选最优、对手选最劣。

骨架 F：非 DP（栈 / 递归下降）

58.4 五条实战铁律

  1. 先问「状态需要几维」 得分/代价是否非线性？是否需要记住「已合并个数」？先定维数再写转移。

  2. 先判断可行性剪枝 57 合并石子的 (n-1) % (k-1)、k == 1 除零、52 的 n == 0 —— 这些 O(1) 判断能挡掉大量无解输入。

  3. 边界一定要单独处理 i == j、空区间、下三角读取。本篇有 4 道题踩过这个坑：

    • 52：L == 2 时 dp[i+1][j-1] 读下三角得到 0；
    • 53：k = i+1 时 dp[i+1][k-1] 读下三角（此处恰好正确）；
    • 56：k = hi = n 时 dp[n+1][n]，数组必须开 n+2；
    • 57：m+1 可能等于 j。

  4. 验证要覆盖多字符集 本篇用穷举 BFS / minimax 验证时发现：很多错误 DP 在二元字符集上完全正确，换成三字符集立刻暴露。 （52 的朴素版本在 {1,2} 上 0 错，在 {1,2,3} 上大量出错。）

  5. 警惕「凭印象」写题面 本篇多次修正：52 的 pal 表缺失、53 的 dp[k][j] 笔误、54 的计分规则（k*k 而非 k*color）、55 的题型（求值而非计数）、56 的代价（x 而非 1）、57 的约束（2 <= k）。 每道题都要核对官方题面原文，尤其是计分规则和约束。
