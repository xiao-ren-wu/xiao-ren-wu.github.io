序列 DP（LIS / LCS / 编辑距离 / 回文）

本页用途

状态从「一维位置」扩到「两个位置」，即dp[i][j]。这一批是 DP 里题型最集中、也最能看出状态定义水平的部分：子序列不连续、子串连续、两个字符串对齐——三种边界条件对应三套写法。

题号与频率

收录 第 16~30 题，面试命中率 ★★★★★。题目编号沿用 动态规划专项 的全局编号。

与本库已有笔记的关系

本批的 编辑距离、通配符匹配、最长回文子串 在本库已有独立笔记。另可对照 不同的子序列 II（计数 DP 的去重技巧）。

每道题的阅读顺序

本页每题统一按① 题意 → ② 暴力解法与瓶颈 → ③ 状态定义（为什么这样定义）→ ④ 转移方程推导 → ⑤ 填表/图解 → ⑥ 初始化与遍历顺序 → ⑦ Java 代码 → ⑧ 手算示例 → ⑨ 复杂度 → ⑩ 常见错误与面试追问 十步展开。 第一次看题解时，②③⑥ 是重点（为什么必须用 DP、状态为什么这么定义、边界为什么这么设）；第二次复习时只看 ④⑨⑩。

0. 本批题的通用骨架

0.1 三种”边界语义”决定了三套写法

序列 DP 的题看似千变万化，实际上只有三种边界语义。认准属于哪一种，代码就定了：

语义含义状态定义不相等时代表题
A. 子序列（可不连续）选或不选，每个位置独立决策dp[i][j] = 前 i、前 j 的最优max(dp[i-1][j], dp[i][j-1])LCS(20)、编辑距离(22)、不同的子序列(24)
B. 子串 / 连续段必须是连续的一段dp[i][j] = 以 i、j 结尾的最优0（断裂，不是继承）最长公共子串(21)、回文子串(26)
C. 区间整个 [i, j] 都要处理dp[i][j] = [i, j] 的最优视情况回文子序列(25)、编辑距离(22)

A 和 B 的”不相等时”处理完全不同，这是本批最大的分水岭

为什么？ 子序列允许跳过字符，所以”A 的前 i 个”可以从”B 的前 j-1 个”继承方案。子串要求连续，一旦两端字符不等，以这两端结尾的公共子串长度就是 0（连长度为 1 的都不成立）。 面试高频陷阱：把 B 写成 A。 写完一定要问自己”这里能跳过字符吗？”

0.2 二维 DP 的四种遍历顺序

dp[i][j] 的遍历方向由依赖方向唯一决定，不能随意选：

依赖遍历顺序涉及题目
左上 dp[i-1][j-1]行正序，j 正序20 LCS、22 编辑距离、30 通配符
上 + 左行正序，j 正序8 不同路径、10 最小路径和
左下 dp[i+1][j-1]行倒序，j 正序25 最长回文子序列
上 + 左下j 倒序（i 可正序）21 最长公共子串

倒序 vs 正序的本质：读”旧值”还是”新值”

一维压缩时，同一个dp[j] 数组被复用：

  • j 正序：dp[j] 还是上一行的（旧的），dp[j-1] 是本行的（新的）
  • j 倒序：dp[j] 和 dp[j-1] 都还是上一行的（都是旧的）

选哪个取决于你的状态需要”旧行”还是”新行”的哪一部分。 这是 DP 优化 第 91 条的核心内容。

16. 最长递增子序列 LIS（LeetCode 300）

① 题意

给定整数数组 nums，求最长严格递增子序列（可以跳过元素，但不能改变顺序）的长度。

② 暴力解法与瓶颈

瓶颈：状态里其实已经带了 last（上一次的结尾值），“到第 i 个位置、上一个结尾是 last”这个状态会被大量重复计算——如果 nums 元素重复，重复程度是指数级的。

③ 状态定义

dp[i] = 以 nums[i] 结尾的最长严格递增子序列的长度

为什么必须”以 i 结尾”？ 同 最大子数组和 的理由——答案可能在任何位置结束（[1,2,3] 的答案以 2 结尾，[5,1,2,3] 以 3 结尾），所以需要：

  • dp[i]：以 i 结尾的最优 → 用来转移
  • ans：全局最优 → 才是答案

“严格递增”意味着转移条件是 nums[j] < nums[i]（不是 <=）。这个细节决定了 nums = [2,2,2] 的答案是 1 而不是 3。

④ 转移方程推导

以 i 结尾的递增子序列，倒数第二个元素（如果存在）必然是某个 j < i 且 nums[j] < nums[i] 的位置。

问题：dp[i] = 1 + max{dp[j] | nums[j] < nums[i]} 里的 max 需要遍历所有 j，O(n²)。能不能不遍历，直接定位？

关键洞察——换一个更”有用”的数组：

tails[k] = 当前所有长度为 k+1 的递增子序列中，结尾元素的最小值

为什么记录”最小结尾”？ 因为结尾越小，后面越容易接上。这与 二分查找索引 的”最左满足条件”是同一个道理。

为什么 tails 严格递增？ 若 tails[k-1] >= tails[k]，则”长度为 k+1 的子序列”（结尾 tails[k]）删掉最后一个元素后，能得到一个”长度为 k、结尾比 tails[k-1] 还小的子序列”，与 tails[k-1] 的最小性矛盾。✅

为什么答案是 size 而不是 max(dp)？ size 始终等于”当前最长递增子序列的长度”，因为 tails 每次更新只会把某个位置的值变小或在末尾追加。

面试追问 1：能还原出

具体的 LIS 吗？ tails 优化版不能（因为 tails 内容可能拼接自不同子序列）。有两种做法：

  1. 朴素 DP + 前驱数组：额外维护 pre[i] = 最优的 j，最后从 argmax(dp) 沿 pre 回溯
  2. tails + 前驱：维护 prevIdx[l] = 产生 tails[l] 时它的前驱在 tails 中的下标，更新时同步记录

面试追问 2：LCIS（最长公共

子序列递增）怎么做？即 [[1,3,5,4,7],[2,4]] 不能把 tails 优化直接搬过来，因为一旦丢掉了”结尾值属于哪个序列的信息”，就无法与第二个序列比对。 必须用二维：dp[i][j] = a 的前 i 个与 b 的前 j 个的 LCIS 长度，O(mn)。 这也说明：tails 优化不是”万能加速”，它牺牲了状态信息。

面试追问 3：为什么这题不能用贪心？

贪心会想”每次选最小的、方便后面接”——这恰恰是 tails 的思路，但它只能保证长度，不能保证方案合法。 换句话说，tails 优化其实是”带状态记忆的贪心”：它记住了每个长度的最优结尾，但没有记住”这个结尾来自哪个具体的元素序列”。 DP 和贪心的边界在这里变得模糊——因为状态空间被压缩成了一个”单调数组”。见 贪心索引。

为什么用”前 i 个”而不是”以 i 结尾”？ 因为 LCS 的答案就是”两个前缀的 LCS”，dp[m][n] 直接是答案，不需要额外的全局 max。 （对比第 21 题”最长公共子串”——那里必须用”以 i、j 结尾”并额外维护全局答案。）

④ 转移方程推导

划分依据（看两个串的最后一个字符）：

“相等”分支的严格论证：若 a[i-1] == b[j-1] == c，则

  • 存在一个最优解包含这个 c（因为把 c 加到任何不含它的 LCS 后面都合法）
  • 这个 c 必然配对（若 c 在解里同时配给了更早的位置，可以把它挪到最后，剩余部分仍是一个公共子序列，长度不减）
  • 所以 LCS = LCS(a前i-1, b前j-1) + 1 ✅

“不相等”分支的严格论证：

  • c = a[i-1]，它不可能是解的最后一个元素（否则需要 b 中也有 c 在末尾，但 b[j-1] != c）
  • 所以可以丢掉 a[i-1]，考虑 dp[i-1][j]
  • 同理可以丢掉 b[j-1]，考虑 dp[i][j-1]
  • 两个丢弃方式都覆盖了所有可能（一个最优解要么没用 a[i-1]，要么没用 b[j-1]，至少有一个成立）→ 取 max ✅

为什么”不相等”时不能写

dp[i-1][j-1]？ 因为 a[i-1] 和 b[j-1] 不能配对，它们不能同时被丢掉。如果两个都丢掉（dp[i-1][j-1]），可能丢失最优解。 反例：a = "ac", b = "ab"。a[1]='c', b[1]='b' 不相等：

  • dp[i-1][j-1] = dp[1][1] = 1（“a”）→ 1
  • max(dp[1][2], dp[2][1]) = max(1, 1) = 1 → 1 这次碰巧一样。换个例子 a = "abc", b = "adc"：
  • dp[2][2] = dp("ab","ad") = 1（“a”）→ 1
  • max(dp[2][3], dp[3][2]) = max(LCS("ab","adc")=2, LCS("abc","ad")=2) = 2 ✅ 必须取 max。

25. 最长回文子序列（LeetCode 516）

必须记住

本题是区间 DP 的入门代表（虽然还有一个更简单的二维写法）。它引出”区间状态”这个重要概念，详见 区间 DP。

① 题意

给定字符串 s，求 s 中最长回文子序列的长度。子序列可以不连续，但必须正着读和反着读一样。

② 暴力解法与瓶颈

瓶颈：只判断”是否回文”不够，我们要求的是”最长”，需要考虑”不选两端”的情况。

③ 状态定义：从”位置”扩到”区间”

dp[i][j] = s[i..j]（闭区间）内的最长回文子序列长度

为什么状态要从”一个位置”扩到”一个区间”？

原因说明
需要两端信息判断子序列是否回文，必须同时看首尾
转移需要”去掉端点”“保留两端”→ dp[i+1][j-1]；“丢掉一端”→ dp[i+1][j] 或 dp[i][j-1]。都需要区间状态
一维状态不够位置状态无法表达”从 i 到 j 这段”

区间 DP 的一句话定义

dp[i][j] = 从 i 到 j 这个闭区间的最优解。 状态有两维（两个端点），但它们不是独立的——i ≤ j 恒成立，所以只有 O(n²) 个有效状态。 枚举顺序必须是”按区间长度”或”让被依赖的区间先算完”。

④ 转移方程推导

划分依据（s 的首尾两个字符怎么处理）：

“相等”时的论证：若 s[i] == s[j] == c，则

  • 存在一个最优解把两个 c 配成一对（不然可以把最外层的某个 c 挪到两端）
  • 所以 dp[i][j] = dp[i+1][j-1] + 2 ✅

“不等”时的论证：

  • s[i] != s[j]，它们不能同时是回文的首尾（否则要求相等）
  • 所以最优解必然至少丢掉一个：dp[i+1][j]（丢左）或 dp[i][j-1]（丢右）
  • 两者取 max ✅

禁忌

dp[i+1][j-1] 在 j == i+1 时会越界！ 当区间只有 2 个字符且相等时（如 "aa"），dp[i+1][j-1] = dp[2][0] —— 左边比右边大，是非法区间。 处理办法（两种）：

  1. 让 dp[i+1][i]（空区间）的值为 0 —— 靠”数组默认值 0”自然成立
  2. 显式特判 j - i < 2 ? 2 : dp[i+1][j-1] + 2

第 1 种更简洁，但要意识到”空区间 = 0”这个约定（见 ⑥ 初始化）。

⑥ 初始化与遍历顺序（区间 DP 的关键）

项结论理由

遍历顺序i 从 n-1 递减到 0；j 从 i+1 递增到 n-1见下
答案dp[0][n-1]

区间 DP 的遍历顺序：

i 必须倒序 转移依赖 dp[i+1][j-1]、dp[i+1][j]（下一行）和 dp[i][j-1]（本行左边）。 所以：

  • i 必须倒序（从 n-1 到 0），保证下一行 i+1 已算完 ✅
  • j 可以正序（dp[i][j-1] 是本行左边，已算完；dp[i+1][j-1] 和 dp[i+1][j] 是下一行，也已算完）✅

如果 i 写成正序，dp[i+1][*] 全是 0，答案会退化成”只统计单字符和相邻的”。

区间 DP 的两种等价遍历方式

方式外层内层优点
按行倒序（本题用）i 从 n-1 递减j 从 i+1 递增代码简洁，天然处理 dp[i][i]
按长度递增len 从 2 到 ni 任意，j = i+len-1概念更清晰（“先算短的区间”）

面试中推荐”按长度”写法，因为它把”区间 DP 必须按长度递增”这个思想表达得最清楚。详见 区间 DP。

为什么本题难以压缩到 O(n)？

转移需要：

  • dp[i+1][j-1]（下一行，左边一格）
  • dp[i+1][j]（下一行，同列）
  • dp[i][j-1]（本行，左边一格）

需要在同一轮里同时访问”下一行的两个相邻格”和”本行左边”，一维数组不够用。 （可以用两个一维数组滚动，但空间仍是 O(n)。） 空间从 O(n²) 降到 O(n) 是可能的（两个滚动数组），但代码复杂度显著上升，面试中通常不要求。区间 DP 是”空间换清晰”的典型代表。

对比第 26 题（最长回文子串）：它可以压到 O(n)（因为状态是 boolean 且转移只需要一格），对比着看很有意思。

① 题意

给定字符串 s，返回 s 中最长的回文子串（连续的子串）。注意返回的是子串本身，不是长度。

② 暴力解法与瓶颈

瓶颈：判断一个区间是否回文要 O(n)，而区间有 O(n²) 个 → 大量重复比较。

③ 思路一：区间 DP（承上启下）

  • 中心扩展：一旦 s[l] != s[r] 立刻停止，随机字符串上平均每个中心只扩展 1 步

随机串上中心扩展接近 O(n)，而区间 DP 永远是 O(n²)。 这是它被面试偏爱的重要原因。 最坏情况（"aaaa...a"）才是 O(n²)。

面试追问 1：Manacher 算法（O(n)）是怎么想的？

核心是复用已知回文的”对称性”：

两个关键点：

  1. 在 [center - c[center], right] 内，位置 i 的回文半径至少是 min(right - i, c[mirror]) → 直接跳过一大部分扩展
  2. right 单调右移，所以总扩展次数是 O(n)

⑤ 阶段二：最少分割 DP

转移：枚举最后一段的左端点 j（0 ≤ j ≤ i）：

为什么枚举”最后一段的左端点”？ 因为分割的最后一刀决定了”哪一段是尾巴”，而”前缀怎么分”是子问题 cut[j-1]。

这是”划分型 DP”的通用转移结构：枚举最后一段的边界，把问题归约为”前缀的最优 + 当前段是否合法”。

面试追问 2：为什么”划分型 DP”总是枚举

最后一段（而不是第一段）？ 两种都行，但最后一段更自然：

  • 枚举第一段：f[i] = min over j ( 1 + f[j+1] )，需要处理”j+1 越界”和下标右移
  • 枚举最后一段：f[i] = min over j ( f[j-1] + 1 )，j 从 0 开始就自然包含了”整段”的情况

从 0 开始的下标（而非 1）让”枚举最后一段”写法更简洁，这是选它的实际理由。

① 题意

LeetCode 44（通配符）：* 匹配零个或多个字符，? 匹配恰好一个任意字符。判断整个 s 是否与整个 p 匹配。

两题的关系

LC 10 的基础子集就是 LC 44（把 ? 换成 .）。DP 框架完全一样，只差一个匹配函数。 本题先讲 LC 44（更清晰），再补 LC 10。

② 暴力解法与瓶颈

瓶颈：'*' 分支里 dfs(s, i+1, p, j)（j 不动）会重复计算”用 * 吸收更多字符”的过程。这是典型的”同一状态被多次到达”，DP 可以缓存。

③ 状态定义

dp[i][j] = s 的前 i 个字符与 p 的前 j 个字符是否完全匹配

“完全匹配”是这个状态的关键——不是”部分匹配”，所以答案就是 dp[m][n]，不用取 max/min。

④ 转移方程推导（本题核心）

划分依据：模式串的最后一个字符是什么。

两个分支的含义（这是全题最关键的理解）：

分支转移语义为什么
① '*' 吸收 0 个dp[i][j-1]把 x* 两个字符从模式里删掉* 允许前面的 x 出现 0 次 → x* 整体消失
② '*' 吸收 ≥1 个dp[i-1][j]s 退一个字符，p 指针不动* 还能继续吸收更多字符，所以模式位置保持 j

分支 ② 是精髓：'*' 吸收了一个字符后，模式串的指针不动（还是 j），因为 * 还在等着吸收下一个。 这正是回溯法 dfs(s, i+1, p, j)（j 不动）的 DP 化。

常见错误：把

dp[i-1][j] 写成 dp[i-1][j-1]

原因：'*' 吸收一个字符后，'*' 自己还在模式里，所以 j 不能减。 只有”匹配 0 个”时（x* 整个消失）才 j 减 1。

另一个常见错误：字符匹配用

p[j-1]

* 是修饰符，它”重复”的是前一个字符 p[j-2]，不是它自己。

含 ( ) 的完整正则（带分组、嵌套、量词）本质上是在模拟一个 NFA。

  • ** Thompson 构造法**：O(mn) 时间和空间
  • ** NFA→DFA + 模拟**：最坏 O(2ᵐ)，但配合 DFA 状态最小化和缓存，实践很快

面试中如果被问”完整的正则匹配怎么做”，说”NFA 模拟，状态是”当前模式位置集合”就足够了。

本题三大高频错误，面试必查

  1. dp[0][j] = dp[0][j-1]（应为 j-2）——初始化的”错位”
  2. * 分支用 dp[i-1][j-1]（应为 dp[i-1][j]）——转移的”错位”
  3. 字符匹配用 p[j-1]（应为 p[j-2]）——语义的”错位”

三个错误都源于”* 是修饰符，它和前一个字符是一组”这个核心语义没有贯彻到底。 记住一句话：x* 是一个整体，要么整个消失（j 减 2），要么至少吃掉一个 x（j 不动）。

面试追问 1：为什么不用回溯/递归？

会超时。 * 的”吸收 k 个”分支会产生指数级复杂度，且大量重复。 DP 的价值在于把”同一个 (i, j) 状态”的结果缓存下来。 面试中如果先用回溯写一版再优化到 DP，是很好的展示过程。

面试追问 2：NFA / DFA 思路（更工程的做法）

正则匹配本质是有限自动机匹配：

  • NFA（非确定）：状态间可以有 ε 转移（'*' 吸收 0 个就是 ε 转移），Thompson 构造法 O(mn)
  • DFA（确定）：java.util.regex.Pattern 内部用的就是 DFA + 记忆化，常数极小

DP 和 NFA 在复杂度上是同阶的（都是 O(mn)），但 NFA 更好并行（状态集合运算天然适合 GPU/位运算）。 知道这个视角能体现对问题的理解深度。

本批的核心收获

序列 DP 的难点不在转移方程，而在三件事：

  1. 状态定义——“前 i 前 j”还是”以 i 结尾”？决定了答案在哪一格
  2. 遍历顺序——正序还是倒序？取决于是否重复读本轮已更新的值
  3. 边界初始化——0 还是 1？是 j-1 还是 j-2？

把这三件事想清楚，剩下的是熟练度问题。
