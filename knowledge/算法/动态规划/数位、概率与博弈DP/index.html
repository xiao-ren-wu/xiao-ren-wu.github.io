数位 DP / 概率 DP / 博弈 DP

本页用途

三类状态带额外维度的 DP： 数位 DP 的状态是 (位置, 是否贴上界)；概率 DP 的状态是 (局面, 轮次)；博弈 DP 的状态是 (局面, 谁走)。 共同点是——把「前缀信息」压进状态，用记忆化搜索写最省事。

题号与频率

收录 第 81~90 题，面试命中率 ★★★。题目编号沿用 动态规划专项 的全局编号。

与本库已有笔记的关系

本批的 数字 1 的个数 在本库 数学与位运算索引 主题下有一个按位统计的详细版本，两种解法互补。

81. 数位 DP 模板（记忆化搜索）

问题形态：给定上界 n（可达 10^9 甚至更大），统计 [0, n] 内满足某种只与数位有关性质的数的个数。

为什么普通 DP 不行：n 有 10 位，逐个枚举要 O(n)；数位 DP 只依赖”当前处理到第几位、之前选了什么”，状态数是 位数 × 状态维度 而不是 n。

核心四元组

记号含义为什么必须有
pos当前处理第几位递归推进的指针
limit已选前缀是否与 n 的前缀完全相同决定本位上界是 n[pos] 还是 9
state与题目相关的额外信息（数位和、出现过的数字集合、上一位是不是 1…）承载题目性质本身
lead是否还停留在前导零阶段数位 DP 最大的坑，见 83⑧

可套用骨架

三条容易写错的地方

  1. 终止条件里做判定。不要写成”每层累加一次 accept(state)”——那样会对同一个前缀重复计数。
  2. limit && d == up 里的 up 是当前这一位的上界。只有 limit 为真时 up 才等于 n 的对应位，所以这个写法在两种情况下都正确。
  3. memo 只在 !limit 时有效。limit == true 的状态只出现一次（沿着 n 的数位），缓存它没有意义，且下标可能越界。

复杂度：设位数为 L、状态维度为 S。时间 O(L × S × 10)，空间 O(L × S)。因为 S 通常很小（数位和 ≤ 81、数字集合 ≤ 2^10），数位 DP 在 n = 10^18 时依然是毫秒级。

五种最常见的 state

题目类型state 取值本批例题
数位和0..9L82（LC 233）
出现过哪些数字0..1023（10 位掩码）83（LC 1012）
上一位是不是 10/184（LC 600）
余数0..M-1「能被 M 整除的数个数」
相邻数位差受限0..K「相邻数位差不超过 K 的数个数」

数位 DP 的 mask 分支就是状压 DP

state 取位掩码时（83 的 10 位数字集合），状态数是 2^10 = 1024，可以直接套 状态压缩 DP 的 [pos][mask] 数组。两类 DP 的边界是人为划的，不是算法上的。

82. 数字 1 的个数（LC 233）

① 题意：给 n（0 ≤ n ≤ 10^9），返回 [0, n] 里所有数的十进制表示中 1 出现的总次数。

n = 13 → 6（官方例 1） n = 0 → 0（官方例 2）

② 核心洞察：不要按”数”枚举，按”数位贡献”枚举

与其遍历每个数看它有几个 1，不如固定一个数位 f = 1, 10, 100, ...，统计”所有数中第 f 位为 1 的个数”，再对所有数位求和。O(n) 变成 O(log n)，这就是本题的全部技巧。

③ 转移：把 n 在数位 f 上拆成三段

设 high = n / (f*10)（f 左边）、cur = (n / f) % 10（f 位上的数字）、low = n % f（f 右边）。

第 f 位为 1 的数分两类：高位已小于 high（之后随便填，共 high * f 个）与高位恰等于 high（本位必须填 1，由 low 决定，共 low + 1 个）。第二类只在 cur ≥ 1 时存在。

cur第 f 位为 1 的个数理由
0high * fcur < 1，第二类不存在
1high * f + low + 1第二类有 low+1 个（low 本身也计入）
≥ 2(high + 1) * f第一类 high*f，第二类 f 个（低位任填）

④ 正确性：三类互斥且穷尽，合计恰为”第 f 位为 1”的全部数。不同数位独立，求和即总次数。

⑤ 手算 n = 13

fhighcurlow该位贡献对应的数
1130(1+1)×1 = 2个位为 1：1, 11
100130×10+3+1 = 4十位为 1：10,11,12,13
1000013循环终止（f > n）—
合计6✓

⑥ 复杂度：时间 O(log n)，空间 O(1)。

⑦ Java 实现

⑧ 边界与易错

  • n = 0 → 循环体一次都不进，返回 0 ✓。
  • f 必须声明为 long。写成 int 时，f = 10^9 之后 f *= 10 得到 10^10 > Integer.MAX_VALUE，溢出成负数，循环条件行为未定义。这是本题唯一的实现陷阱。
  • 返回类型 int 是官方签名；n ≤ 10^9 时最大答案是 900000001 < 2^31，安全。但 n 一旦超过约 2.1×10^9 答案就会溢出（n = 2×10^9 时答案是 2.8×10^9，int 直接变负数）。面试时若出题人放开 n，需改成 long。
  • cnt 也应改成 long 才与上面一致。

⑨ 面试变体

  • 推广到「数字 d 的个数」：在三分支里加 cur == d 的判断即可。
  • 「二进制中 1 的个数」：f 从 10 进制权重改成 2 进制权重（f <<= 1），转移变成 high*f + (cur==1 ? low+1 : f)。
  • 「二进制表示里没有连续 1 的数个数」→ 见 84。

⑩ 相关：数字 1 的个数（本库另一份按位贡献的详细版）、数学与位运算索引。

83. 至少有 1 位重复的数字（LC 1012）

① 题意：给 n（1 ≤ n ≤ 10^9），返回 [1, n] 中至少有一位数字重复出现的正整数个数。

n = 20 → 1（只有 11）。（官方例 1） n = 100 → 10（11~99 共 9 个，加上 100）。（官方例 2）

② 核心洞察：总数减去「各位互不相同」的数

[1, n] 一共 n 个数，所以答案 = n - (各位互不相同的数个数)。后半部分就是数位 DP + 10 位掩码。

③ 状态与转移

记号含义
pos当前处理到第几位（高位在前）
mask已用数字集合，第 d 位为 1 表示 d 出现过（0..1023）
limit前缀是否与 n 相同
lead是否还在前导零阶段

本位选数字 d：

  • lead && d == 0 → 仍是前导零，mask 不变，lead 保持 true。
  • 否则 (mask & (1 << d)) != 0 → d 重复，该分支直接剪掉。
  • 否则 mask |= 1 << d，lead 置 false。

叶子：只有 lead == false（至少选了一个非零数字）才计 1，因为题目只数正整数。

④ 正确性：mask 恰是已用数字集合，重复即剪枝，故叶子枚举出的正是「各位互不相同」的所有数；lead 排除了 0 本身。总数相减得答案。

⑤ 手算 n = 100

把 [1, 100] 拆成一位数 / 两位数 / 三位数，统计其中「各位互不相同」的个数，再用 100 减。

类别范围各位互不相同的个数算式
一位数1~999 个数天然互不相同
两位数10~9981十位 9 种（19），个位 9 种（09 中去掉十位那个）→ 9×9
三位数1000含两个 0，重复
合计909 + 81
答案10100 - 90 ✓ 官方例 2

十位不可能是 0（那就不是两位数了），所以两位数直接是 9 × 9，不需要再额外排除任何东西。90 - 81 = 9 个不合规的两位数正是 11, 22, ..., 99。

⑥ 复杂度：L 位、2^10 个掩码。时间 O(L × 2^10 × 10)，空间 O(L × 2^10)。L ≤ 10 时约 10^5 个状态，毫秒级。

⑦ Java 实现

⑧ 边界与易错

  • lead 是头号坑。两处都要对：① 转移里 lead && d == 0 时 mask 保持不变；② 初始调用的 lead 必须是 true——pos = 0 此刻确实还处于前导零阶段。写成 dfs(0, 0, true, false) 会让数字 0 本身被当成”各位互不相同”计入 distinct，于是 n = 1 返回 1 - 2 = -1，n = 100 返回 28 而不是 10。
  • 不区分前导零的话，mask 的第 0 位会记录”出现过 0”，于是 1024（含两个 0）和 10 都会被误剪。规则是 lead && d == 0 时 mask 保持不变。
  • memo 的第二维是 mask（0..1023）不是 pos。维度顺序写反会下标越界。
  • n = 10^9 的答案是 994388230。10^9 本身有 10 位且含两个 0，所以位数要开到 10，不能只开 9 位。

⑨ 面试变体

  • 「恰好有 k 位重复的数个数」：mask 换成一个 repeatCount，或直接 DFS 计数。
  • 「n 位 01 串中含子串 101 的个数」：state 换成”已匹配 101 的前缀长度”（KMP 自动机，3 状态）。
  • 「十进制表示不含 0 的正整数个数」：lead 恒为 false，d 从 1 枚举。

⑩ 相关：状态压缩 DP（mask 即状压）、数字 1 的个数。

84. 不含连续 1 的非负整数（LC 600）

① 题意：给 n（1 ≤ n ≤ 10^9），返回 [0, n] 中二进制表示不含连续两个 1 的数的个数。

输入输出合规的数来源
550,1,2,4,5（3 = 11 不合规）官方例 1
120,1官方例 2
230,1,2官方例 3

② 核心洞察：先算「自由位」的方案数，再逐位贴上界

一旦某一位开始不再受 n 约束，剩下的位怎么填都合规——此时方案数只取决于「还剩几位」。这构成 Fibonacci 递推。

③ 递推

设 f[i] = 长度为 i、不含连续 1 的二进制串个数（允许前导零）。

按第一位分类：填 0 → 剩 i-1 位自由，f[i-1] 种；填 1 → 第二位被迫填 0，剩 i-2 位自由，f[i-2] 种。

递推初值展开
f[i] = f[i-1] + f[i-2]f[0] = 1（空串）、f[1] = 2（0、1）f[i] = Fib(i+2)

④ 贴上界的扫描

n 的第 i 位为 1 时有两种合法走法：

  • 本位填 0 → 变小，从此脱离上界，后 i 位自由 → 贡献 f[i] 个。
  • 本位填 1 → 继续贴上界，合法当且仅当第 i+1 位不是 1。

于是从高到低扫：遇到 1 就 ans += f[i]，再检查更高一位是不是 1——若是，说明 n 自己就有连续 1，扫描到此为止（n 本身不合法，不能 +1）。全程无冲突则最后 +1 计入 n 自己。

顺序是「先累加

f[i]，再判冲突」 先判冲突再累加，会漏掉「在冲突位之前就已分叉」的那批数，答案偏小。

⑤ 手算 n = 5（101）

in 的第 i 位动作ansprev
21ans += f[2] = 331
10跳过，prev = 030
01ans += f[0] = 1；prev == 0 不冲突41
结束return ans + 15✓

f[2] = 3 对应”第 2 位填 0”的三种低位填法：000、010、100，即 0、2、4 —— 正是比 5 小且合规的那些。

⑥ 复杂度：时间 O(32)（固定扫 32 位），空间 O(32)。

⑦ Java 实现

⑧ 边界与易错

  • 1 << 30 合法，1 << 31 溢出成 Integer.MIN_VALUE（负数）。循环必须止于 30，写成 i < 32 会在最后一步读到负的按位结果。
  • 末尾的 +1 是 n 自己。漏掉它，所有本身不含连续 1 的 n 都会少 1。
  • n = 10^9 的答案是 2178309 = Fib(32)，看起来”比 f[30] 还大”其实正好等于 f[30]：因为 10^9 < 2^30，而最大的 30 位无连续 1 的数是 0x2AAAAAAA = 715827882 < 10^9，所以 [0, 10^9] 把全部 30 位合法串都收进来了。

⑨ 面试变体

  • 「区间 [l, r] 内不含连续 1 的数个数」：findIntegers(r) - findIntegers(l-1)。
  • 「长度为 n 的 01 串中不含 11 的个数」：直接答 Fib(n+2)，不涉及上界。
  • 「不含 101 的数个数」：换 3 状态 KMP 自动机。

⑩ 相关：数学与位运算索引（本题是位运算与 DP 的交界处）。

85. 抛掷硬币（LC 1230）

① 题意：n 枚硬币，第 i 枚正面概率是 prob[i]。每枚各抛一次，返回恰好 target 枚正面的概率。

输入输出来源
prob = [0.4], target = 10.4官方例 1
prob = [0.5]×5, target = 00.03125官方例 2

约束：1 ≤ n ≤ 1000，0 ≤ prob[i] ≤ 1，0 ≤ target ≤ n，误差容忍 10^-5。

② 状态定义

dp[j] = 处理完前若干枚硬币后，恰好 j 枚正面的概率。滚动数组，一维即可。

初值 dp[0] = 1（还没抛时，0 枚正面的概率是 1），其余为 0。

③ 转移

处理一枚正面概率为 p 的硬币后，新的 j 枚正面有两种来源：原来 j 枚且本次反面（概率 dp[j]·(1-p)），原来 j-1 枚且本次正面（概率 dp[j-1]·p）。

$$\text{new}[j] = dp[j],(1-p) + dp[j-1],p$$

一维数组必须从大到小更新。若从小到大，dp[j-1] 已经是本轮的新值，等于把这枚硬币算了两次。

④ 正确性：全概率公式按”本次正/反”划分，互斥且穷尽。倒序更新保证读到的 dp[j]、dp[j-1] 都是上一轮的值。

⑤ 手算 prob = [0.4], target = 1

轮dp[0]dp[1]
初始10
处理 p = 0.41×0.6 = 0.60×0.6 + 1×0.4 = 0.4
答案0.4 ✓

prob = [0.5]×5, target = 0：dp[0] = 0.5^5 = 0.03125 ✓

⑥ 复杂度：时间 O(n × target)，空间 O(target)。

⑦ Java 实现

⑧ 边界与易错

  • target 可以是 0（官方例 2 就是）。所以循环条件必须是 j >= 0，不能写 j >= 1；并且 j == 0 时那一项就是 dp[0] *= (1-p)。漏掉 target = 0 这条分支会直接答错官方例 2。
  • j 必须倒序。正序会重复计数。用一维数组时这是最容易犯的错。
  • 上界可用 Math.min(target, 已处理枚数) 收窄以提速，但不能用 Math.min(target, n) 当固定上界然后从 target 开始——虽然结果相同（dp[j] 对 j > 已处理枚数 恒为 0，乘 (1-p) 仍为 0），但白白多算。写 Math.min(target, n) 不算错，只是不够快。
  • target > n 时 dp 数组够大但全为 0，返回 0，正确（虽然官方保证 target ≤ n）。

⑨ 面试变体

  • 「抛 n 次硬币，至少出现 k 次正面的概率」= Σ_{j≥k} dp[j]。
  • 「每枚硬币的 p 不独立 / 有依赖」→ 状态要加维度，见 86。
  • 「连续 k 次正面」→ state 记”当前连续正面个数”，矩阵快速幂可加速。

⑩ 相关：86、87 是本页另外两道概率 DP。

86. 骑士在棋盘上的概率（LC 688）

① 题意：n × n 棋盘，骑士从 (row, column) 出发走恰好 k 步。每步从 8 个方向中等概率选一个走。返回走完后仍在棋盘上的概率。

输入输出来源
n=3, k=2, row=0, column=00.0625官方例 1
n=1, k=0, row=0, column=01.0官方例 2

约束：1 ≤ n ≤ 25，0 ≤ k ≤ 100。

② 核心语义（本题唯一的坑）

题目原文：“它每次从 8 个可能的走法中等概率随机选一个（即使那步会走出棋盘）”。

所以无论当前格子有几个合法走法，每一步都除以 8。落在棋盘外的概率质量直接丢失（骑士”走出棋盘”就结束了）。

这不是 bug，而是题意。 官方例 1 正是靠这条才得到 0.0625：

步存活分布推导
0(0,0) = 1起点
1(1,2) = 1/8，(2,1) = 1/88 个方向只有 2 个落在盘内，各得 1/8；另外 6 个方向出界，概率质量直接丢弃
2(2,0) = 1/64，(0,0) = 2/64，(0,2) = 1/64从 (1,2) 分出 (2,0)、(0,0)；从 (2,1) 分出 (0,0)、(0,2)，各乘 1/8
合计4/64 = 0.0625存活概率 = 最后一层全盘求和 ✓ 官方例 1

③ 状态与转移

dp[i][j] = 走完当前步数后位于 (i, j) 的概率。答案是最后一层 dp 的全盘求和。

$$\text{next}[x][y] \mathrel{+}= \frac{dp[i][j]}{8},\quad (x,y) = (i+\Delta x,\ j+\Delta y)\ \text{且在盘内}$$

④ 正确性：每步从 8 个方向等概率取一个，落在盘内的概率质量累加到对应格子，出界的丢弃。归纳可得每层 dp 正确，求和即存活概率。

⑤ 复杂度：时间 O(k × n² × 8) = O(k n²)，空间 O(n²)（用滚动数组）。

⑥ Java 实现

⑦ 边界与易错

  • 恒除 8，不要除以”盘内合法方向数”。后者会得到完全不同的答案，且与官方例 1 矛盾。
  • k = 0 → 循环不进，直接返回 dp[r][c] = 1 ✓
  • 必须用滚动数组，不能原地更新 dp——否则本步新产生的概率会在同一步内继续传播，等价于走了两步。
  • dp[i][j] == 0 时 continue 是安全优化；但不能改成 if (dp[i][j] < 1e-9) continue，那会漏掉合法的小概率质量（k = 100 时概率可以小到 8^-100）。

⑧ 面试变体

  • 「棋盘是 m × n 的矩形」：只改数组大小和边界判断。
  • 「每步 4 个方向各有不同概率」：/8 换成该方向的概率。
  • 「返回骑士最终位置的完整概率分布」：不求和，直接返回最后一层 dp。

⑩ 相关：数学与位运算索引。

87. 新 21 点（LC 837）

① 题意：Alice 从 0 分开始，只要分数 < k 就继续抽牌，每次从 [1, maxPts] 等概率抽一个。抽到 ≥ k 立即停止。返回最终分数 ≤ n 的概率。

输入输出来源
n=10, k=1, maxPts=101.0官方例 1
n=6, k=1, maxPts=100.6官方例 2
n=21, k=17, maxPts=100.73278官方例 3

约束：0 ≤ k ≤ n ≤ 10^4，1 ≤ maxPts ≤ 10^4，误差容忍 10^-5。

② 状态定义

dp[i] = 以 i 分结束的概率。因为分数严格递增，每个 i 最多被到达一次，所以这个量良定义；i < k 表示”还没停牌”，i ≥ k 表示”正好停在这里”。

初值 dp[0] = 1。

③ 转移

$$dp[i] = \frac{1}{\text{maxPts}} \sum_{j=\max(0,,i-\text{maxPts})}^{\min(i-1,,k-1)} dp[j]$$

  • 下界 i - maxPts：最后一次抽的牌最大是 maxPts。
  • 上界 min(i-1, k-1)：只有 j < k 才会继续抽牌。j ≥ k 表示已经停牌，不该再作为前驱。

答案是

$$\sum_{i=k}^{n} dp[i]$$

答案

不是 1 - Σ_{i<k} dp[i] 差一点的总和是 1，但缺的正是”停牌分数落在 (n, +∞)”的那部分概率。n = 6, k = 1 时正确答案 0.6，而 1 - dp[0] = 0（因为 dp[0] = 1 恒成立），这个式子会输出 0。要么直接对 [k, n] 求和，要么写成 1 - Σ_{i<k} dp[i] - Σ_{i>n} dp[i]。

④ 滑动窗口优化

求和区间是 [i - maxPts, i-1] ∩ [0, k-1]，随 i 递增左右端点都只增不减，所以可以维护一个滑动和 sum，把每次转移从 O(maxPts) 降到 O(1)。

维护 sum 的两条规则：

  • if (i < k) sum += dp[i]; —— 只有 i < k 的分数还会继续抽牌，才要纳入窗口。
  • if (i - maxPts >= 0 && i - maxPts < k) sum -= dp[i - maxPts]; —— 移出离开窗口的项，并确认它当初确实进过窗口。

早退：k == 0（一开始就停）或 n ≥ k - 1 + maxPts（最大可能分数都 ≤ n，概率必为 1）。

早退用

k - 1 + maxPts 而不是 k + maxPts 抽最后一张牌之前分数至多 k-1（否则早停了），最后一张至多 maxPts，所以最大总分是 k-1+maxPts。用更松的 k + maxPts 结论仍然正确（只是晚一步返回 1.0），但 k-1+maxPts 更紧。

⑤ 手算 n=6, k=1, maxPts=10

k=1 表示抽一张就停，所以 dp[1..10] = 1/10 各自（从 0 分一步到达），答案 = 6 × 0.1 = 0.6 ✓

⑥ 复杂度：朴素 O(n × maxPts)，滑动窗口后 O(n)，空间 O(n)。

⑦ Java 实现

⑧ 边界与易错

  • sum 的移出条件里那个 < k 不能省。若 i - maxPts ≥ k，说明 dp[i-maxPts] 当初就没被加进 sum（因为它 ≥ k），此时再减一次就把别人的份额减掉了，sum 会变成负数。
  • i = k 时 dp[k] 必须计算（它表示”恰好停在 k 分”），所以 dp[i] = sum/maxPts 要对所有 i 执行，只有 sum += dp[i] 才受 i < k 限制。混淆这两者是本题最常见的错误。
  • k = 0 → 早退返回 1.0。
  • n = k → 答案是 dp[k]（只可能恰好停在 k 分）。

⑨ 面试变体

  • 「每次抽牌区间不均匀」→ dp[i] = Σ_j dp[j] × w[i-j]，退化成卷积，可以 NTT。
  • 「求最终分数恰好为 n 的概率」→ 直接返回 dp[n]。
  • 「求期望分数」→ Σ_i i × dp[i]（注意只对 i ≥ k 求和）。

⑩ 相关：85、86 是本页另外两道概率 DP。

88. 石子游戏 II（LC 1140）

① 题意：n 堆石子排成一行。Alice 先手，每次可以取走最左边的 X 堆（1 ≤ X ≤ 2M），然后令 M = max(M, X)，初始 M = 1。Bob 同规则。返回双方最优时 Alice 能拿到的最大石子数。

输入输出来源
[2,7,9,4,4]10官方例 1
[1,2,3,4,5,100]104官方例 2

约束：1 ≤ n ≤ 100，1 ≤ piles[i] ≤ 10^4。

② 零和性质：只需算「分差」

两人拿的总量固定为 Σ piles，所以「Alice 最大化自己的石子数」等价于「Alice 最大化 自己 - 对手 的分差」。

于是定义 dp[i][m] = 在还剩 [i, n-1] 且 M = m 的局面下，当前行动者相对对手的最大分差。

关键点：因为是零和，对手的最优分差就是 -dp[i+x][m']，所以

$$dp[i][m] = \text{suf}[i] - \min_{1 \le x \le \min(2m,, n-i)}\ dp[i+x][\max(m,x)]$$

其中 suf[i] = Σ_{t≥i} piles[t]，m' = max(m, x)。取 x 到 n-1 时后继分差为 0（石子取完了）。

等价地写成 max( suf[i] - dp[i+x][max(m,x)] )，两者等价（零和 ⇒ 减最小 = 减负最大）。

③ 剪枝：能一次拿完就全拿

若 2m ≥ n - i，当前行动者可以一次取完所有剩余石子，于是 dp[i][m] = suf[i]。这一步把大量状态直接短路，是本题通过 n ≤ 100 的关键。

④ 递推顺序：i 从大到小（dp[i+x] 依赖更大的 i），m 从小到大都可以（m 只在同 i 内被读，且 m' ≥ m 时也不依赖同 i 的其他 m）。

⑤ 手算 [2,7,9,4,4]

步Alice 拿局面Bob 拿Alice 拿Alice 合计
11 堆 2[7,9,4,4]，M=1 → dp[1][1]，且 2×1 ≥ 4 不成立2 堆 7,92 堆 4,42+4+4 = 10
22 堆 2,7[9,4,4]，M=2 → 2×2 ≥ 3 成立，Bob 全拿3 堆全拿—2+7 = 9
最优max(10, 9) = 10 ✓

⑥ 复杂度：O(n²)（i 有 n 档、m 有 n 档、每个 m 枚举 2m 个 x，合计 O(n² log n) 上界，剪枝后实测 O(n²) 量级）。空间 O(n²)。

⑦ Java 实现

⑧ 边界与易错

  • nm = max(m, x) 不会越界，尽管看起来 max(m,x) 最大能到 2n：因为循环条件里有 i + x <= n，所以 x ≤ n - i ≤ n，于是 nm ≤ n。数组开 dp[n][n+1] 刚好够。这个”看起来会越界其实不会”的点很容易让人误加 Math.min，加了也不影响正确性但说明没想清楚。
  • n = 1 → 2m ≥ n-i = 1 成立，直接返回 piles[0] ✓
  • m 必须从 1 开始（M 初始为 1，且 M = max(M, X) ≥ 1）。
  • 别在同一个 i 上用”已经算出的 best”再乘 0 之类的东西凑转移——那是最容易写出”死代码 + 自我覆盖”的地方。转移只写一次、写对一次。

⑨ 面试变体

  • 「石子游戏 III」（LC 1143）：同样的思路，dp[i][j]，问能否取到最大和（改成布尔/极值判定）。
  • 「石子游戏 IX」（LC 2029）：两端取 + 奇偶分类。
  • 「每次取 1..X 堆」：M 换成显式的 X 参数，状态变成 dp[i][X]。

⑩ 相关：90 是博弈 DP 的总览，两题配合看。

89. 猫和老鼠（LC 913）

① 题意（本节曾整节归错题，此处为核实后的事实）

归题纠错

本节此前描述的是”老鼠在 0、猫在n-1、谁先到对方终点谁赢”的无和赛跑，并写了 minCatMousePlay。 这是错的：LC 913 是下述的三值博弈；minCatMousePlay 是 LC 1728「Cat and Mouse II」（网格 + 食物 + 跳跃长度），与 913 无关。 下面按 LC 913 的真实题面重写。

LC 913 Cat and Mouse：

  • 无向图，graph[a] 是 a 的所有邻点。洞在节点 0。
  • 老鼠从节点 1 出发并先手，猫从节点 2 出发后手。
  • 每回合必须沿一条边移动。猫不能进入洞（节点 0）。
  • 三种结局：猫与老鼠同节点 → 猫胜；老鼠到达 0 → 鼠胜；局面重复（两者位于与之前某回合相同的位置，且轮到同一个人走）→ 平局。
  • 返回 0 平局 / 1 鼠胜 / 2 猫胜。
输入输出来源
测试图（邻接表，graph[a] 是 a 的邻点集合）输出来源
:-----:---::---
graph[0]={2,5}, graph[1]={3}, graph[2]={0,4,5}, graph[3]={1,4,5}, graph[4]={2,3}, graph[5]={0,2,3}0（平局）官方例 1
graph[0]={1,3}, graph[1]={0}, graph[2]={3}, graph[3]={0,2}1（鼠胜）官方例 2

约束：3 ≤ n ≤ 50，2 ≤ graph[i].length < n，graph[1]、graph[2] 非空。

② 状态：必须加「轮到谁走」这一维

局面 (m, c) 不足以定胜负——同一个 (m, c)，轮到老鼠走和轮到猫走结果可能完全相反。所以状态是三元组：

记号含义
ans[m][c][0]老鼠在 m、猫在 c、轮到老鼠时的结局（0 未定/平局，1 鼠胜，2 猫胜）
ans[m][c][1]同上，轮到猫走
deg[m][c][t]该局面的合法后继数，已被确定的后继每确定一个就减一

deg 的初值：deg[m][c][0] = graph[m].length（老鼠的走法）、deg[m][c][1] = graph[c].length - (0 ∈ graph[c] ? 1 : 0)（猫不能进洞）。

③ 逆向拓扑（Retrograde Analysis）

不从初局往前搜，而是从所有已知结局的局面往回推。这是博弈 DP 处理”允许平局”的标准手法。

种子局面（结局已定，入队）：

  • 老鼠在洞里：m == 0（c ≥ 1）→ 鼠胜，两种 t 都置 1。
  • 猫抓到老鼠：m == c（m ≥ 1）→ 猫胜，两种 t 都置 2。

出队一个已定局面 (m, c, t)，其结果为 r，它的前驱是 (pm, c, pt) 与 (m, pc, pt)，其中 pt = t ^ 1：

  • 若 pt == 1（前驱是猫走）→ 前驱由 (m, pc) 构成，pc ∈ graph[c] 且 pc != 0。
  • 若 pt == 0（前驱是老鼠走）→ 前驱由 (pm, c) 构成，pm ∈ graph[m]。

对每个尚未确定的前驱 P：

  • 若 r 是 P 里该走那人的胜利（r == 1 && pt == 0，或 r == 2 && pt == 1），说明走一步就能赢 → 立刻把 P 定为 r 并入队。
  • 否则这个后继对走棋者不利 → --deg(P)；deg 减到 0 说明所有后继都不利 → P 定为 r 并入队。

④ 平局是怎么”掉出来”的

必须记住

0 同时表示「未定」和「平局」，这是算法的精妙处 状态初值是 0（未定），而只有鼠胜（1）和猫胜（2）会被写入并入队。BFS 跑完后仍是 0 的状态，说明没有任何一方能强制取胜——双方都能保证自己不输，于是结果是平局。 所以最后的 return ans[1][2][0]（老鼠在 1、轮到老鼠）直接就是答案，0 自动代表平局，不需要额外判定。

这也解释了为什么终止条件里不需要单独讨论平局：平局是”推不出来”的自然结果。

⑤ 正确性要点：deg 计数为何不会把平局误判成某方胜

设前驱 P 轮到老鼠走（pt == 0）。被 deg 计入减一的后继，必然满足”r 不是鼠胜”，即 r ∈ {2}——因为入队局面的 r 只可能是 1 或 2（0 是不确定态，从不入队）。所以所有被减一的后继都是 r = 2（猫胜），deg 减到 0 时把 P 定为 2 是自洽的。

这就是「0 既是未定又是平局」带来的额外好处：入队的值非 0，所以 deg 的语义始终干净。

⑥ 复杂度：状态 2n²，每个状态被处理一次、每个状态枚举一次出边。总时间 O(n² · Δ)（Δ 为最大度数，可写成 O(n²) 于稠密图），空间 O(n²)。

⑦ Java 实现

⑧ 边界与易错

  • 终止条件不是”某一方到达终点”，而是”老鼠在 0”或”猫与老鼠同节点”。写成”某一方无路可走”是彻底跑偏（那是无和赛跑的模型）。
  • ans 是三维的，漏掉 t 这一维会得到完全错误的答案——(m,c) 相同但轮到不同人走时优劣常常相反。
  • deg 初始化时必须扣掉猫进洞的那条边，且要扣在正确的状态上：合法的猫走后继少一个的是”猫就在洞的邻点”的那些状态，即 deg[m][c][CAT_TURN]（m 任意、c ∈ graph[0]）。写成”鼠在洞的邻点”（c 任意、prev ∈ graph[0]）会灭错方向：猫在洞邻点的状态 deg 偏高、永远判不出（假平局），牵连出一堆假猫胜/假鼠胜。这是最容易写错又最难测出的一行。
  • 猫的前驱枚举里 pc == HOLE 必须 continue 跳过，与 deg 的扣减保持一致。
  • 前驱已确定（!= TIE）时 continue，避免重复入队。
  • 返回 ans[1][2][MOUSE_TURN]：老鼠起点 1、猫起点 2、老鼠先手。三个值任一写错，结果就变了。

⑨ 面试变体

  • 「不允许平局 / 谁先走出某图」（纯抢点）：退化成 dp[m][c] 两维，无 t 也无 deg，直接记忆化。
  • 「谁先到终点」型（对称赛跑）：零和分差 DP，见 90 的 predictTheWinner 思路。
  • 「Nim / 取最后者赢」：Sprague-Grundy，比记忆化更强（可合并子游戏）。
  • 「多玩家博弈」：t 维从 2 扩到玩家数，但 deg 减到 0 的推理不再成立（需要 SG 函数或极大极小）。

90. 预测赢家（LC 486）与博弈 DP 总览

① 题意（LC 486）

nums 数组，两人轮流从两端取数（nums[0] 或 nums[n-1]），取走即计分，直到取空。返回先手能否得分不低于后手（平局也算先手赢）。

输入输出来源
[1,5,2]false官方例 1
[1,5,233,7]true官方例 2

约束：1 ≤ n ≤ 20，0 ≤ nums[i] ≤ 10^7。

② 状态与转移：零和分差 + 只能取两端

dp[i][j] = 在 [i, j] 这段上，当前行动者相对对手的最大分差。

$$dp[i][j] = \max\big( nums[i] - dp[i+1][j],; nums[j] - dp[i][j-1] \big),\quad dp[i][i] = nums[i]$$

答案 dp[0][n-1] >= 0（>= 0 因为平局算赢）。

③ 为什么必须写两个端点

只能从两端取，所以转移只有两项。写成”可以取任意 k”是错的——那会算出 [17,5,16,6,18] 先手赢，而正确答案是先手输（手算 dp[0][4] = max(17-23, 18-22) = -4）。

奇偶配对策略只对偶数长度有效

常见结论”总数为偶数时先手必胜（取奇数位或偶数位中较大的一侧）“只在 n 为偶数时成立。n 为奇数时后手握有奇偶优势：[17,5,16,6,18] 总和 62（偶）但 n=5（奇），先手仍然输。所以别把”总和为偶 → 先手赢”当结论用。

④ 复杂度：时间 O(n²)，空间 O(n²)（可滚动到 O(n)）。

⑥ 博弈 DP 的三种写法（本批总结）

写法状态何时用本批例题
零和分差dp[i][...] = 相对分差双方都以”多拿”为目标，零和88（LC 1140）、90（LC 486）
极大极小 + 记忆化dp[m][c][t] → 赢/输只需知道”谁能赢”，允许平局89（LC 913）
逆向拓扑ans[m][c][t] + deg状态多、可能平局、正向搜会爆89（LC 913）

选择依据：能不能零和化。能（分差）就零和分差，最简洁；不能（只想知道赢输、且有平局）就上 t 维；状态空间太大时把记忆化换成逆向拓扑，让复杂度只与”被确定的局面数”成正比。
