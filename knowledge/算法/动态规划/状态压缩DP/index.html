状态压缩 DP

本页用途

当问题本质是**「从一个集合里选若干个」**，且集合大小 n ≤ 20 时，把集合编码成整数的二进制位，于是「状态」变成一个数字，可以直接放进数组。TSP、划分 K 组、火柴拼正方形、我能赢吗都属于此类。

判定口诀：能不能只用一个 int 描述”我已经做了哪些事”？ 能，就可以状压。

题号与频率

收录 第 71~80 题，面试命中率 ★★★。题目编号沿用 动态规划专项 的全局编号。

其中 71（模板）和 80（总结）不是 LeetCode 原题，77（LC 1531）其实不是状压 DP，故意放在这里当反例。

与本库已有笔记的关系

关键技巧是sub = (sub - 1) & mask 枚举子集、lowbit = mask & (-mask) 定位最低位。 若状态无法压成一个 int（集合太大 / 元素是字符串 / 需要记录”上一段连续了多长”），参见 序列 DP 与本文件第 77 题。

71. 状压 DP 模板：位运算工具箱

① 建模：把集合变成 int

一个含 n 个元素的集合，用第 i 位表示”第 i 个元素在不在集合里”。

集合二进制十进制
空集00000
{0}00011
{0,2}01015
{1,2}01106
{0,1,2}01117

于是”并集”变成 |，“是否包含”变成 &，“加入 i”变成 mask | (1 << i)，“移除 i”变成 mask ^ (1 << i)。

② 不用状压的瓶颈

TSP 的暴力是枚举 n! 种全排列。n = 10 时 3.6×10⁶，n = 15 时 1.3×10¹² —— 不可行。 状压把它降到 O(2ⁿ · n²)：n = 15 时约 7×10⁶，n = 20 时约 4×10⁸（偏大但可接受）。

状压的代价是 2ⁿ，所以 n ≤ 20 是硬门槛。 n 到 25 就该考虑 树形 DP 与换根 或 DP 优化 里的折半搜索了。

③ 状态定义

模板本身不解决具体题，它提供三个”状态探针”：

  • popcount(m)：集合大小（用了几个元素）
  • lowbit(m)：最低位的 1，对应唯一元素
  • submaskCount(m)：子集个数 = 2^popcount(m)

④ 转移：枚举子集的两种写法

写法 A：从大到小走 sub（要求 sub 真子集）

(sub-1) & m 一次性跳到”下一个更小的子集”，总次数 = 2^popcount(m)。

写法 B：带上 0（把 m 自己也算进去）

这是唯一正确的”含 0”写法。直接写 for (int sub = m; sub >= 0; sub = (sub-1) & m) 会死循环——因为 sub == 0 时 (0-1) & m == m，又回到起点。

⑤ 手算：枚举 {0,1,2} 的所有子集

m = 111(=7)，(sub-1) & m 的轨迹：

sub二进制说明
7111m 本身
61106 的二进制减 1 得 110，& 111 = 110
5101
4100
3011
2010
1001
00001 减 1 得 0，& 111 = 0

每个子集恰好出现一次，共 8 个 = 2^3。

⑥ 遍历顺序

只要转移总是”往集合里加元素”，mask | (1 << i) > mask 恒成立（数值严格变大），所以按 mask 从小到大遍历就是合法拓扑序，不需要任何标记数组。

反之，如果转移是”减少元素”（如 mask & ~(1 << i)），那就必须倒序遍历，或用记忆化搜索。

⑧ 手算示例

popcount(0b10110)：22 = 10110，22 & 21 = 20，20 & 19 = 16，16 & 15 = 0 → 循环 3 次 → 3。 isPowerOfTwo(16)：16 & 15 = 0 → true。 forEachSubmask(0b101, f) 应回调 4 次（101, 100, 001, 000）。

⑨ 复杂度

全部 O(1)（popcount 最多 32 次循环，可视为常数）。forEachSubmask 回调次数 = 2^popcount(m)。

⑩ 常见错误与面试追问

四个高频坑

  1. 1 << n 在 n ≥ 31 时溢出。 Java 里 1 << 31 == Integer.MIN_VALUE（负数），1 << 32 == 1（回到原点!). 需要 n ≥ 31 的位集时用 long（1L << n）或 java.util.BitSet。n ≤ 20 的状压不受影响。
  2. for (int sub = m; sub >= 0; sub = (sub-1) & m) 死循环，因为 sub=0 时又变回 m。
  3. 第 0 位被浪费。 LC 464 用 1 << i（i 从 1 开始）表示”数字 i 是否用过”，第 0 位永远为空转。不影响正确性（只是白白浪费 1 位），但读代码时容易误判。
  4. Integer.bitCount 已被 JIT 优化成单指令，手写 m &= m-1 循环并不更快，只是更直观。

面试追问

  • Q：状压的上限 20 是硬的吗？ 不是。2ⁿ 空间意味着 n=25 需要 1.3×10⁸ 个状态，内存就爆了。折半搜索（meet-in-the-middle）能把 2ⁿ 降到 2^(n/2)，n 到 40 都能做。
  • Q：为什么 TSP 是 O(2ⁿ·n²) 而不是 O(2ⁿ·n)？ 因为状态里除了 mask 还要记”当前在哪”（n 种），再枚举下一个城市（n 种）。见第 72 题。
  • Q：能不能用 HashSet 代替位掩码做状压？ 能，但慢 20 倍以上，且无法做 O(1) 的位运算判断。位掩码的本质就是把集合塞进一个机器字，让集合运算降为单指令。

72. 旅行商问题 TSP

① 题意

n 个城市，两两之间有距离 dist[i][j]。从城市 0 出发，每个城市恰好访问一次，最后回到城市 0，求最短总距离。dist 可以是非对称的。

② 暴力解法与瓶颈

枚举 n! 个全排列。n=10 时 3.6×10⁶（可接受），n=15 时 1.3×10¹²（不可行）。

剪枝版暴力：从 0 出发做 DFS，剪掉”当前距离 ≥ 已知最优”的分支。这是面试常写的版本，但最坏仍是 O(n!)。

③ 状态定义

dp[mask][i] = 从城市 0 出发，恰好访问过 mask 中的城市，当前停在城市 i 的最短距离。

两个维度缺一不可：

  • mask 记录”去过哪些”，用于保证不重复、不遗漏
  • i 记录”现在在哪”，用于决定下一步的距离

只写 dp[mask] 是无法转移的 —— 同样的已访问集合，停在不同城市的后续代价不同。

④ 状态转移推导

从 dp[mask][i] 出发，走向一个还没访问过的城市 j：

$$dp[mask \mid (1 \ll j)][j] = \min\big(dp[mask \mid (1\ll j)][j],\ dp[mask][i] + dist[i][j]\big)$$

条件：i ∈ mask（当前城市必须在已访问集合里）且 j ∉ mask。

收尾（所有城市都访问完后，还要买一张回 0 的机票）：

$$\text{ans} = \min_{i \ne 0}\Big(dp[(1\ll n)-1][i] + dist[i][0]\Big)$$

⑤ 填表过程

取 3 城，dist = [[0,2,3],[2,0,1],[3,1,0]]：

mask含义dp[mask][i]（来源）
001走过的城市 {0}，停 0dp[001][0] = 0（起点）
011{0,1}，停 1dp[001][0] + dist[0][1] = 0 + 2 = 2
101{0,2}，停 2dp[001][0] + dist[0][2] = 0 + 3 = 3
111全访问，停 1dp[101][2] + dist[2][1] = 3 + 1 = 4
111全访问，停 2dp[011][1] + dist[1][2] = 2 + 1 = 3

收尾：

  • 停 1 回 0：4 + dist[1][0] = 4 + 2 = 6
  • 停 2 回 0：3 + dist[2][0] = 3 + 3 = 6

答案 6。 两条环路 0→1→2→0 = 2+1+3 = 6、0→2→1→0 = 3+1+2 = 6 都是 6，与填表一致 ✓

⑥ 初始化与遍历顺序

  • dp[1][0] = 0（1 = 1<<0，只访问了城市 0，停在 0，代价 0）
  • 其余全部 INF = Integer.MAX_VALUE / 2
  • 为什么是 MAX_VALUE/2 而不是 MAX_VALUE？ 因为要执行 dp + dist。若 INF = MAX_VALUE，任何一次 INF + dist 都会整数溢出成负数，污染答案。除法 2 是为了留出加法空间。
  • 按 mask 从小到大遍历：转移目标是 mask | (1<<j) > mask，天然拓扑序。

⑦ Java 代码

⑧ 手算示例

dist = [[0,2,3],[2,0,1],[3,1,0]] → 6（见 ⑤）。 全对称 2 城：[[0,3],[3,0]] → 走 0→1→0 = 3+3 = 6。 单城：[[0]] → 0（这是最容易漏的边界，收尾循环 i=1..n-1 一次都不执行，会返回 INF）。

⑨ 复杂度

时间 O(2ⁿ·n²)，空间 O(2ⁿ·n)。n=15 时 2^15 × 15 × 15 ≈ 7.4M 状态，n=20 时约 4×10⁸ —— 后者应改用”状态压缩 + 空间优化”（滚动掉 i 维仍需 2ⁿ·n）或 Held-Karp 的剪枝版本。

⑩ 常见错误与面试追问

四个坑

  1. n = 1 返回 INF。 收尾循环从 i = 1 开始，n=1 时不执行。必须提前 if (n <= 1) return 0;。本页 5575 条断言里有 41 条专门卡这个。
  2. 漏掉”回到起点”。只算 min(dp[full][i]) 是”最短哈密顿路径”，不是回路。
  3. INF = Integer.MAX_VALUE 导致溢出。 永远用 MAX_VALUE / 2。
  4. 忘记 if (dp[mask][i] == INF) continue;。 虽然 INF + dist 仍是很大的正数、min 不会选它，但当 dist 存在负数时（某些变体）会出错。加上更稳。

面试追问

  • Q：为什么这个叫 Held-Karp？ 它是 TSP 的经典 O(2ⁿ·n²) 精确解，1960 年由 Held 和 Karp 各自独立提出。
  • Q：n 很大怎么办？ ① 折半搜索：把城市分成两半，O(2^(n/2)·n²) 合并，n 到 40 左右。② 若是几何 TSP（距离是欧氏距离），有平面图性质，可用 Christofides 给出 1.5-近似。③ 工程上直接用 OR-Tools / 模拟退火。
  • Q：dist 对称能优化吗？ 可以。dist[i][j] == dist[j][i] 时，dp[mask][i] 与 dp[full^mask][j] 存在对称关系，可省一半空间，但实现复杂度上升，面试一般不提。

73. 划分为 K 个相等的子集（LC 698）

① 题意

数组 nums（n ≤ 16，元素 1..10⁴）能否划分成 k 个元素和相等的非空子集？注意是恰好 k 个，不是”至多 k 个”。

② 暴力解法与瓶颈

把 n 个元素分配到 k 个盒子里，每个盒子最终和相等。回溯：逐个元素放入 4 个盒子之一，剪枝条件是”某盒已超重”或”某盒为空时又跳过一根”。

最坏 O(kⁿ)，n=16、k=16 时 1.6×10¹⁹ —— 不可行。瓶颈在于状态只记”放了多少”不够，必须记”放在哪些”。

③ 状态定义

dp[mask] = 已经放进盒子的元素集合恰好是 mask 时，当前这个盒子已填的数之和。

看起来只存一个标量很可疑 —— 难道不用记”当前是第几个盒子”？关键洞察：

已填长度 = (被选中元素的总和) mod target，其中 target = sum / k。 而”被选中元素的总和”完全由 mask 决定。所以 dp[mask] 是 mask 的函数，一个标量够用。

这也是本题最漂亮的地方：省掉了”当前在第几个盒子”这一维。

④ 状态转移推导

从 dp[mask] 出发，选一个还没用的元素 nums[i] 放进当前盒子：

  • 若 dp[mask] + nums[i] > target：当前盒子已满，放不下了 → 跳过
  • 否则：继续往当前盒子放 $$dp[mask \mid (1\ll i)] = (dp[mask] + nums[i]) \bmod target$$

取模的含义：当 dp[mask] + nums[i] == target 时，取模得 0，表示”当前盒子刚好装满，自动开启下一个空盒子”。这一行代码同时表达了”填满”和”换盒”两件事。

① 题意

② 题目最容易读错的地方

“累计整数和”是

④ 状态定义与记忆化

为什么 memo 只需要 mask 一维？ 因为 rest = desiredTotal - (已用数字之和)，而已用数字之和完全由 mask 决定。所以 rest 是 mask 的函数，不必单独做 key。

同理，dfs 里的 max 参数在整次调用中是常量，也不进 key。

⑤ 状态转移推导

  • rest <= 0 → 上一手已经让累计和达标了 → 轮到的人输，返回 false
  • 否则，枚举每个没用过的 i：
    • 若 dfs(mask | (1<<i), max, rest - i) 返回 false（对手必败）→ 当前玩家赢

75. 最小的必要团队（LC 1125）

① 题意

req_skills 是必需技能列表，people[i] 是第 i 个人掌握的技能。选出规模最小的团队，使团队合起来覆盖所有必需技能。返回人员下标（任意顺序）。官方保证有解。

约束：req_skills.length ≤ 16，people.length ≤ 60，people[i].length 可以为 0。

② 暴力解法与瓶颈

关键判断：状压的是技能，不是人！

  • 状压人：people.length ≤ 60 → 2⁶⁰，不可能
  • 状压技能：req_skills.length ≤ 16 → 2¹⁶ = 65536 ✓

这是本题的核心识别点。想到这一层，暴力（枚举人员子集求最小）就不必要了。

③ 状态定义

  • p[i] = 第 i 个人掌握的技能的位掩码

题目要返回人员下标。只存最小人数无法还原答案，所以 DP 值直接存一条最优路径。 另一个选择是”计数 DP + 单独回溯数组 g[i]/h[i]”，空间更省（2 个 int 数组而非 List），但代码更长。n ≤ 16、m ≤ 60 时 List 版本完全够用。

76. 火柴拼正方形（LC 473）

① 题意

n 根火柴（n ≤ 15，长度 ≤ 10⁸），每根不折断、每根恰好用一次，能否拼成一个正方形。

② 暴力解法与瓶颈

从 n 根中分出 4 组，每组和相等。回溯：把每根火柴尝试放进 4 个盒子之一。

无剪枝 O(4ⁿ) = 10⁹（n=15），不可行。瓶颈是”已经用了哪些火柴”这个子集信息没有进入状态。

③ 状态定义：为什么 1 维 memo 就够（本题最漂亮的洞察）

朴素想法是 dfs(mask, cur, ...) 需要两维状态（已用集合 + 当前边长度）。但注意：

$$\text{cur} = \text{sum(已用火柴)} \bmod \text{side} = \Big(\text{totalSum} - \text{sum(未用火柴)}\Big) \bmod \text{side}$$

已用集合确定 → cur 唯一确定。 所以 cur 是 mask 的函数，只需一维 memo。

这里藏着一个极易犯的错

mask 的含义必须和 dfs 的语义严格一致。原笔记的模板里：

  • if (mask == 0) return true; → 这是”全部用完”的意思，所以 mask 必须表示”已用集合”
  • if ((mask & (1 << i)) != 0) continue; → “已被用掉”跳过 → 同样是”已用”语义
  • 但初始调用写的是 dfs((1 << n) - 1, 0) —— 全 1 表示”全用完”，与”已用”语义完全相反！

结果：进入 dfs 时所有位都是 1，循环里每一根都被 continue 掉，函数立刻返回 false。任何可行输入都会返回 false。 正确写法是 dfs(0, 0)（初始什么都没用）。

④ 状态转移推导

(cur + len) % side：装满一条边就自动归零，开始下一条边。

⑤ 填表过程

⑥ 两条关键剪枝

剪枝一：同层同长度去重

同一层搜索中，相同长度的火柴是完全等价的 —— 换一根试试没区别，试一次就够。这能把 4ⁿ 压掉一大截。

剪枝二：cur == 0 时直接 break

cur == 0 意味着”刚开始一条新边”。此时如果第一根候选火柴放上去后整个搜索失败，那么换成任何一根也都会失败 —— 因为”用哪些剩余火柴组成剩余几条边”这个问题与”第一根选哪根”完全对称（对称性论证）。所以可以立刻放弃整层。

为什么一定要

降序？ ① 长火柴先放，尽早触发 cur + len > side 的失败，快速剪枝； ② 降序后 sticks[0] 就是最长的一根，于是 if (sticks[0] > side) return false; 这个预处理剪枝才真正生效。

原笔记写的是 Arrays.sort(sticks)（升序）却把注释写成”降序”，导致 sticks[0] 是最短的 —— 那条剪枝等于形同虚设（它永远不会触发，因为最短的必然 ≤ side）。注释和代码不一致，是最隐蔽的一类 bug。

  • Q：火柴长度有 10⁸ 而 n ≤ 15，为什么不按长度开数组？ 长度维度太大，必须状压。这正是”状压优于数值 DP”的典型场景。

77. 压缩字符串 II（LC 1531）

① 这题其实不是状压 DP —— 放在这里是当反例

先破除误解

行程长度编码（Run-Length Encoding）要统计连续段的长度。一旦允许删除字符，不同的同字符段会合并（官方示例 2 就依赖这一点）。 合并意味着”末段有多少个字符”无法由”处理到第几个字符”推出，必须把段长也纳入状态 → 状态膨胀到 O(n·k·c)，已经不是干净的状压。

结论：能用状压的前提是”状态只由集合决定”。本题的状态还依赖”上一段有多长”，所以退回二维 DP + 枚举末段。 判断方法：写状态定义时问自己”这个量是不是 mask 的函数？“——本题答案是”不是”。

② 题意

给定字符串 s（长度 ≤ 100）和整数 k，删除最多 k 个字符，使剩下的字符串行程长度编码长度最小。

行程长度编码规则：连续相同字符段，若段长 t ≥ 2 编码为 字符 + t的十进制；若 t == 1 只输出字符，不附加 ‘1’。

seg(t) = 0 (t=0), 1 (t=1), 1 + 位数(t) (t≥2)

③ 暴力解法与瓶颈

枚举删掉哪些字符（2ⁿ 个子集），对每个子集算 RLE 长度取最小。n ≤ 100 → 2¹⁰⁰ 不可行。n = 20 尚可，n = 100 靠暴力过不了。

瓶颈：不同删除方案的差异只体现在”每段保留多少个”。

④ 状态定义（关键：末段可跨删除合并）

best[i][j] = 把 s[0..i) 处理成 RLE，恰好删除 j 个字符时的最小编码长度。

末尾段的处理方式：设 c = s[i-1]，找出 s[0..i) 中所有等于 c 的位置 p₁ < p₂ < ... < p_m（p_m = i-1）。若末段保留 g 个 c（即位置 p_{m-g} .. p_{m-1}）：

  • 末段最左位置 start = p_{m-g}
  • 区间 [start, i) 里被删掉的个数 del = (i - start) - g
  • 段代价 cost(g) = seg(g)
  • 前缀是 s[0..start)，还需删除 j - del 个

$$best[i][j] = \min\Big(\ best[start][j - del] + seg(g)\Big)$$

再补一条转移处理”末尾字符被删掉”：best[i][j] = min(best[i][j], best[i-1][j-1])。

为什么”末段可以由不连续的同字符组成”？

因为同一段里的字符都相同，删掉其中任意一个的效果完全一样。所以”删掉段中间的字符”总可以等价地改写成”从段的末尾删”。于是我们只需考虑”末段保留末尾 g 个 c，中间的全部删掉”这一种规范形式 —— 转移因此完备。

这正是官方示例 2 的解法：删掉中间的 bb，前后两段 aa 合并成 aaaa。

⑤ 填表过程

s = "aabbaa"，k = 2，i = 6，c = 'a'，{p} = {0, 1, 4, 5}，m = 4。

最终答案取 min(best[n][0..k])（题目是”最多删 k 个”，不是”恰好”）。

⑥ 初始化与遍历顺序

  • best[0][0] = 0，其余 INF
  • 按 i 从小到大遍历：所有转移都指向更小的 start ≤ i（g ≥ 1 时 start < i）和 i-1，天然拓扑序
  • k >= n 时直接返回 0（删光，空串编码长度 0）
  • ⚠️ 位数要算进长度：seg(t) = 1 + 位数(t)，不能当常数。官方示例 3 ("aaaaaaaaaaa", k=0) → 3（“a11”）就是在考这个。

⑩ 常见错误与面试追问

四个坑

  1. 只允许”原串连续”的同字符合并。这样写无法得到官方示例 2（必须删掉中间的 bb 才能让 aa 合并成 aaaa）。这是本题最主要的失分点。

  3. 忘了计数的位数。"a11" 长度 3，不是 2。
  4. 把”最多删 k 个”当成”恰好删 k 个”。答案应取 min 而不是直接取 best[n][k]。

面试追问

  • Q：为什么这题不用状压？ 因为段长不是”已处理字符集合”的函数。用状压的判据是”状态只与集合有关”，本题不满足。
  • Q：如果不限制 k ≤ n 呢？ k ≥ n 时直接返回 0（删光）。这是最省事也最正确的处理。
  • Q：n 到 10⁵ 怎么办？ O(n²k) 已经到 10¹⁰，必须换思路：先用 O(n) 求出所有极大相同段，再对”段”做 DP（段数远小于 n），或者用”保留 k 个字符 + 代价函数可分解”的结构做 DP 优化 里的斜率优化。

78. 优美的排列（LC 526）

① 题意

用 1..n 构造一个排列 perm，使得对每个位置 i（1-based），perm[i] 能被 i 整除或 i 能被 perm[i] 整除。求满足条件的排列个数。n ≤ 15。

② 暴力解法与瓶颈

枚举 n! 个排列逐一检查。n=15 → 1.3×10¹²，不可行。

关键观察：第 i 位放哪个数，只与”哪些数已被使用”有关 —— 因为位置 i 是由”已放了几个数”唯一确定的（i = 已用数个数 + 1）。于是状态可以压缩掉”位置”这一维。

③ 状态定义

dp[mask] = 已经用掉 mask 中的数字、填好了前 popcount(mask) 个位置时的方案数。

位置由 mask 隐含给出：pos = Integer.bitCount(mask) + 1。这是本题省掉一维的关键。

④ 状态转移推导

下一个要填的位置是 pos。对每个未用的数字 v = i + 1，若满足

$$v \bmod pos = 0 \quad\text{或}\quad pos \bmod v = 0$$

则可以放上去：

$$dp[mask \mid (1\ll i)] \mathrel{+}= dp[mask]$$

两个方向都要判（v 可能比 pos 大，例如 pos=1, v=任意；pos 也可能比 v 大，例如 pos=6, v=2）。

⑤ 填表过程

n = 2，dp[0] = 1：

mask已用个数pos = 个数+1可放的 v判定新 mask累加
000111%1=0 ✓01dp[01] += 1
000122%1=0 ✓10dp[10] += 1
011222%2=0 ✓11dp[11] += 1
101212%1=0 ✓11dp[11] += 1

dp[11] = 2 ✓

（两个排列：[1,2] 和 [2,1]。逐位检查 [2,1]：位置 1 放 2，2%1=0 ✓；位置 2 放 1，2%1=0 ✓。合法。）

⑥ 初始化与遍历顺序

  • dp[0] = 1（空排列算 1 种）
  • 按 mask 从小到大：目标 mask | (1<<i) > mask，天然拓扑序
  • 答案 dp[(1<<n)-1]
  • 数组大小 1 << n：n=15 时 32768，毫无压力

⑨ 复杂度

时间 O(2ⁿ·n)，空间 O(2ⁿ)。n=15 → 32768 × 15 ≈ 0.5M，瞬时完成。 这正是 n 敢定到 15 的原因。

⑩ 常见错误与面试追问

两个坑

  1. 只判一个方向。只写 v % pos == 0 会漏掉 [2,1,3] 这类（pos=2, v=1 时是 pos % v == 0）。会得到 1 而不是 2。
  2. pos 算错。用 bitCount(mask) + 1 而不是 bitCount(mask)，因为位置是 1-based。

面试追问

  • Q：怎么发现”位置可以省掉”？ 关键提问：“如果我知道已用集合，能否推出当前要填第几个位置？“本题答案是能（就是集合大小）。凡是能用这个问法省掉一维的题，都能状压。
  • Q：这题和 LC 526 之外还有什么像的？ 排列计数类：LC 1079（字母牌型数，需 DP + 计数 Map）、LC 1873（可同时工作的最大数）。共同点是”状态 = 已用集合”。
  • Q：n 到 20 还能做吗？ 2²⁰ = 10⁶，可以，答案可能超 int 需 long。

79. 不同子序列的个数（LC 940）

① 题意

给定整数数组 nums（n ≤ 1000，1 ≤ nums[i] ≤ 100），求不同的非空子序列个数（按元素值序列去重，不是按下标去重）。

注意：计的是非空。nums = [1,2,3] 的答案是 7，不是 8。

② 为什么这题不是状压 DP

子序列的数量是 2ⁿ 级别（n=1000），远超位掩码能力；且元素有重复时位掩码完全失效（选了下标 0 和下标 2 的 1 是同一个子序列）。

但它和状压有同一个思想内核：都在处理”选一个子集”，只是这里用”去重计数”代替了”枚举子集”。

③ 状态定义

  • dp[i] = 前 i 个元素的不同子序列个数（含空序列）
  • last[x] = 元素 x 上一次出现的 0-based 下标，没出现过为 −1

④ 状态转移推导

处理 nums[i-1] = x 时，新的子序列分成两类来源：

  • 旧子序列（dp[i-1] 个）
  • 旧子序列每个都追加一个 x（dp[i-1] 个）

合计 2 × dp[i-1]。但如果 x 之前出现过，“追加 x”的那批里有一部分与更早的子序列完全重复。

重复的恰好是 dp[last[x]] 个 —— 因为”以前那次 x 充当结尾”的子序列，就是把此前 dp[last[x]] 个子序列各追加一个 x。现在又要追加一次，重复了。

$$dp[i] = 2 \times dp[i-1] - \begin{cases} dp[last[x]] & \text{若 } x \text{ 出现过} \ 0 & \text{否则} \end{cases}$$

为什么要减

dp[last[x]] 而不是 dp[i-1] 重复的不是所有旧子序列，而是”以 x 结尾”的那部分。它们的数量由上一次 x 的位置决定，不是由当前 i 决定。

同时 dp[0] = 1（空序列）必须初始化，否则全盘归零。

⑤ 填表过程

nums = [1, 2, 1]，dp[0] = 1：

ix = nums[i-1]2 × dp[i-1]last[x]（本次读取）减去dp[i]
112 × 1 = 2−102
222 × 2 = 4−104
312 × 4 = 80dp[0] = 17

dp[3] = 7（含空）→ 返回 7 - 1 = 6（非空）。

手工核对 [1,2,1] 的不同非空子序列：[1]、[2]、[1,1]、[1,2]、[2,1]、[1,2,1] → 6 ✓

⑥ 初始化与下标语义（本题最易错处）

last 存的是 0-based（i-1），而 dp 的下标是 1-based（dp[0..n]）。这个错位恰好是自洽的：上次出现在 1-based 下标 j 时 last[x] = j-1，而我们要减的是 dp[j-1]。所以代码是对的，但读起来极易误判。

  • last 数组开 101 大小（因为 nums[i] ≤ 100）。若题目改成 nums[i] ≤ 10⁹，就必须换成 HashMap，复杂度仍是 O(n) 但常数变大。
  • 答案取 dp[n] - 1，减掉空序列。

⑨ 复杂度

⑩ 常见错误与面试追问

三个坑

  1. dp[0] 没初始化为 1。会导致整条链全是 0，答案恒为 0。
  2. 忘记减空序列。[1,2,3] 会得 8 而不是 7。
  3. last 和 dp 的下标基准搞混。两者一个 0-based 一个 1-based，但组合起来恰好自洽 —— 改任何一边都要重新推。

面试追问

  • Q：和 LC 940 字符串版有什么区别？ 字符串版（distinctSubseqII，输入 s，1 ≤ |s| ≤ 2000）答案要对 10⁹+7 取模，且用 dp[26] 记录”以某字符结尾的子序列数”。数组版因为答案不超 int 所以不用取模。两题的 last 数组含义不同，别串。
  • Q：为什么这题能 O(n)？ 因为”不同子序列个数”有闭式递推，不需要真的枚举集合。状压 DP 则是老老实实枚举 2ⁿ 个集合 —— 能用递推化简时，一定要想到还有化简这条路。
  • Q：元素无重复时会怎样？ 此时 last 全部为 −1，dp[i] = 2·dp[i-1] = 2ⁿ，退化成”任意子集都不同”。这时才可以用位掩码 DP，但直接算 2ⁿ 更快。

决策流程

识别口诀

三句话判断是不是状压

  1. 有没有一个”选/不选”的 0-1 决策？ 有 → 考虑状压。

本页实测抓出的真实缺陷（做一遍自检清单）

8 个真 bug + 5 个 oracle bug

笔记的真 bug（已修）

  1. TSP n=1 返回 INF —— 收尾循环从 i=1 起，n=1 时不执行。41 条断言卡住。
  2. LC 473 初始 mask 反了 —— dfs((1<<n)-1, 0) 应为 dfs(0, 0)，导致所有可行输入都返回 false。
  3. LC 473 排序方向与注释不符 —— Arrays.sort 是升序，sticks[0] > side 这条剪枝因此检查的是最短火柴，等于无效。
  4. LC 940 缺 dp[0]=1 —— 答案恒为 0。
  5. LC 940 忘了减空序列 —— [1,2,3] 得 8 而非 7。
  6. LC 464 memo 跨调用不清理 —— key 不含 (max,total)，复用实例必错（9 条断言卡住）。
  7. LC 1531 只允许连续同字符合并 —— 得不到官方示例 2 的 "a4"。
  8. LC 1125 的 req 写成 req.get(i) —— String[] 没有 get。

我自己的 oracle 写错了 5 次（都是”测试失败但笔记是对的”）

  1. LC 698 的 target 传了 0，从未计算 sum/k → oracle 恒返回 false。
  2. LC 464 把”池子空了但没达标”当成对方输。
  3. LC 464 改成”双方各自得分”模型 —— 和官方”共享累计和”语义不符。
  4. LC 464 的 desiredTotal=0 应返回 true。
  5. LC 940 的暴力把空子序列算进去了。
  6. LC 1531 暴力里 1 << n 在 n ≥ 32 溢出，循环范围错误。

两条必须遵守的方法论

① 分歧时先怀疑 oracle。 本项目 14 次”失败”里有 6 次是我自己写错了暴力。写完暴力，先在人工可算的样例（单点、2 点、链、全同）上验一遍再上随机。 ② 随机测试会掩盖”全盘返回 false”的 bug。 LC 473 那个致命错误，在 800 个随机用例里只暴露 10 个 —— 因为大部分随机输入本来就无解，两边都返回 false 就”通过”了。必须硬编码官方样例和有解的构造样例。

面试高频问答

问题回答要点
状压的 n 上限是多少？空间 2ⁿ 是硬约束。n ≤ 20 常规，n = 25 内存爆。更大用折半搜索降到 2^(n/2)。
状压一定能替代搜索吗？不能。状压是”DP 化的搜索”，若状态里还缺信息（LC 1531 的段长），就必须额外加维或改表示。
mask 该存”已用”还是”未用”？必须与 dfs 的语义严格一致。这是 LC 473 致命 bug 的根源。判断法：看 dfs 里 continue 掉的是已用还是未用。
为什么 TSP 要 O(2ⁿ·n²)？mask 记集合，i 记当前位置，转移再枚举下一个城市 j。多出来的 n 来自”当前位置”。
状压能压”字符串”吗？不能直接压。若字符串长度 ≤ 20 可以当集合（每个位置一个 bit），但要注意同一字符出现在多个位置时会重复计数，见 LC 940。
0/1 背包为什么用位掩码？背包的”选不选每个物品”本身就是集合决策。但注意：如果物品数 > 20，标准 O(n·W) 的数值 DP 反而更优。状压不是背包的最优解，只是解法之一。
