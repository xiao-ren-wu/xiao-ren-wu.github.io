背包问题（01 / 完全 / 多重 / 分组）

本页用途

背包不是一类新算法，而是线性 DP 的一种状态设计：把「已经用了多少容量」当成状态。本批的全部差异只来自几个旋钮——物品能用几次、容量有几个维度、求什么、方案算组合还是排列。

题号与频率

收录 第 31~45 题，面试命中率 ★★★★★。题目编号沿用 动态规划专项 的全局编号。

与本库已有笔记的关系

背包是唯一必须背下循环顺序的 DP：01 背包逆序枚举容量，完全背包正序。写反了含义就变了。 线性 DP 与一维递推 的第 14 题「零钱兑换」是最小值版本，本批的 35 题是它的计数版本。

j-- / j++ 01 背包和完全背包的代码逐字符相同，只有内层循环方向相反。

背包类型内层容量为什么
01 背包j = W; j >= w[i]; j-- 逆序保证 dp[j-w[i]] 还是”上一轮”的值，即这件物品没被选过

这唯一的差别，决定了”每件物品用一次”还是”用无数次”。 面试官最爱问的就是这个。

求”最大值”vs”最小值”vs”计数”：初值怎么定

目标初值理由聚合方式
求最大值0什么都不装 = 0，是安全下界max
求最小值INF若填 0，min(0, 1) 恒为 0，答案永远是 0min
求方案数dp[0] = 1，其余 0凑 0 有且仅有 1 种（空方案）+=
求可达性dp[0] = true，其余 false同上|= / ||

求最小值时初值填 0 是最隐蔽的 bug

正确做法：Arrays.fill(dp, n + 1); 再 dp[0] = 0;（第 38 题演示）。

判据：初值必须是”什么方案都没有”的合法值。求最大值时那是 0，求最小值时那要够大，计数时那是 1（空方案）。

31. 01 背包（模板）

① 题意

有 n 件物品，第 i 件的重量是 w[i]、价值是 v[i]。有一个容量为 W 的背包，每件物品最多选 1 次，求能装下的最大总价值。

这是所有背包题的基础。后面 13 道题都是它的变体。

② 暴力解法与瓶颈

枚举每件物品”选 / 不选”，共 2^n 种选择：

瓶颈：2^30 ≈ 10 亿，n = 30 时就已经超时。

但暴力解法本身给了我们转移方程的线索：dfs(i, rest) = max(不选第 i 件, 选第 i 件)，这正是后面 dp[j] = max(dp[j], dp[j-w] + v) 的来源。

③ 状态定义

dp[j] = 容量为 j 的背包，能装下的最大总价值

关键点说明
状态是容量，不是物品下标因为外层循环已经在枚举物品了，内层只需要记”装多重”
”≤ j” 还是 ”= j”？”≤ j”。所以 dp[j] 单调不减，且 dp[W] 就是答案
初值为什么是 0？容量 j 可以什么都不装，价值 0。求最大值时 0 是安全的下界
为什么不记”用了几件物品”？每件物品重量固定，选了它就占用 w[i] 容量——容量信息已隐含物品信息

④ 转移方程推导

对第 i 件物品，只有两种决策：

  1. 不选：dp[j] 保持原值
  2. 选：容量从 j 变成 j - w[i]，价值增加 v[i]

“不重不漏”论证：任何最优解对第 i 件物品要么选要么不选，两类互斥且穷尽，所以取 max。

⑥ 初始化与遍历顺序

项结论理由
dp 初值全 0求最大值时，“什么都不装 = 0” 是合法且安全的下界
外层枚举物品每件物品只被考虑一次（由循环结构保证）
内层逆序 j = W; j >= w[i]; j--关键：保证 dp[j-w[i]] 读到的还是”没考虑第 i 件”时的值
起点j = w[i]（不是 W+1）容量小于重量时装不下，从 w[i] 开始顺带避免负下标
答案dp[W]状态定义是”容量 ≤ W”

逆序为什么必需？写个循环就懂

假设w[i] = 2, v[i] = 3，且 dp 初始全 0，W = 4。

正序会怎样（j = 2; j <= 4; j++）：

j执行dp[j]含义
2dp[2] = dp[0] + 33用 1 件
3dp[3] = dp[1] + 33用 1 件
4dp[4] = dp[2] + 3 = 3 + 36❌ 用了 2 件！

j=4 时读到的 dp[2] = 3 已经是本轮用过一次这件物品的结果，再 +3 就相当于用了两次 → 退化成完全背包。

逆序则不同（j = 4; j >= 2; j--）：

j执行dp[j]
4dp[4] = dp[2](仍是 0) + 33
3dp[3] = dp[1](仍是 0) + 33
2dp[2] = dp[0] + 33

读 dp[2] 时 j=2 还没执行，所以 dp[2] 仍是初始值 0 → 每格最多贡献 1 件 ✅

⑩ 常见错误与面试追问

常见错误后果正确做法
内层写成正序变成完全背包，同一件被重复选01 背包必须逆序
内层从 j = 0 开始dp[j - w[i]] 负下标越界从 j = w[i] 开始
求”恰好装满”却用 0 初始化无法区分”没装”和”装了但价值 0”用 -1 标记不可达（见第 39 题）
价值为负时仍用 0 初始化初值 0 反而成了最优解用 -INF 初始化
返回 dp[W-1]少算一格答案就是 dp[W]

面试追问 1：为什么空间能压到 O(W)？能再压吗？

因为dp[j] 只依赖上一轮的同下标和上一轮的 j-w[i]，所以用一个数组原地更新即可。 还能压：如果只需要最终答案、不需要还原方案，可以把”物品”维也滚掉——但那需要”先按重量排序 + 只能求某些特殊情形”，一般不这么做。O(W) 已经是这类问题的理论最优空间。

枚举每种凑法的硬币序列（有序）：

瓶颈：凑 5 = 1+2+2 和 5 = 2+1+2 会被数两次 → 大量重复计算。

③ 状态定义

dp[j] = 用已处理过的硬币，凑出金额 j 的组合数

关键点说明

组合 vs 排列：靠

外层循环对象区分

  • 组合（顺序无关） → 外层枚举物品（硬币），内层枚举金额

这是本批最重要的一组对比，也是第 36 题的核心。

④ 转移方程推导

对当前硬币 c：

  1. 不用它：dp[j] 旧值保持（这部分方案本来就存在）
  2. 至少用一枚它：去掉一枚 c 后，剩下的是”用已可用硬币凑 j - c”的方案数 = dp[j - c]（本轮值）

“不重不漏”论证（组合的正确性关键）：

  • dp[j] 旧值 = 凑出 j 且不含当前硬币 c 的方案数
  • dp[j - c]（本轮值）= 凑出 j - c 且可以含 c 的方案数，给每个方案加一枚 c，就得到凑出 j 且至少含一枚 c 的全部方案
  • 两类互斥（是否含 c）、穷尽 → 加法原理 ✅

外层硬币顺序为什么能去重？ 每种组合都可以唯一分解为”第 1 枚硬币取 a₁ 枚、第 2 枚取 a₂ 枚、……”。 因为外层硬币顺序固定，DP 只会沿这一个分解路径展开 → 每种组合被数且仅被数一次。

  • 25 % 8 = 1 ≠ 7，不走 return 4
  • 枚举 i = 1：rest = 25 - 1 = 24，非平方数
  • 枚举 i = 2：rest = 21，非平方数
  • 枚举 i = 3：rest = 16 = 4² → return 2 ❌

  • 求最大值：什么都不选的得分为 0，且 0 是所有方案的下界 → min/max 都能正常工作

  • 求计数：空方案有且仅有 1 种 → dp[0] = 1

一条判据统一三者：初值 = “空方案”的合法取值。

39. 恰好装满与至少装满（背包的初始化专题）

① 题意

这是一类模板题的总览，不是某道具体的 LeetCode 题。经典表述：

有 n 个物品，第 i 个物品的体积 size[i]、价值 value[i]。 有一个容量为 V 的背包，每件物品最多用 1 次。求：

40. 多重背包（LeetCode 1159 / 二进制拆分）

① 题意

有 N 种物品，第 i 种物品有 c[i] 件，每件的体积 w[i]、价值 v[i]。求容量 V 的背包能装下的最大价值。

第 i 种物品最多只能用 c[i] 次，介于 01 背包（1 次）和完全背包（无限次）之间。

② 暴力解法与瓶颈

直接三重循环展开成 01 背包：

瓶颈：c[i] 很大时（如 c[i] = 10^9）完全不可行。

关键观察：c[i] = 13 和 c[i] = 10000 都不需要真的展开那么多件 —— 只需要 O(log c[i]) 个”虚拟物品”。

③ 状态定义

二进制拆分的核心思想

c[i] = 13 件可以拆成 1 + 2 + 4 + 6 四组。 每一组当作一件 01 物品（重量 = k * w[i]，价值 = k * v[i]），可选或不选。

① 题意

有 k 组物品，每组里有若干件物品，每组最多选一件。第 g 组第 t 件的体积 w[g][t]、价值 v[g][t]。求容量 V 的背包的最大价值。

这是本批唯一的”三层循环”背包。 关键在于：同一组内的物品是互斥的（选了 A 就不能选 B）。

瓶颈：组数多、每组件数多时爆炸。

关键观察：这是**“在每组里挑一件”**的最优化 → 组是天然的”阶段”，用滚动数组即可。

③ 状态定义

dp[j] = 处理完当前若干组后，容量 ≤ j 的背包的最大价值

注意：这是”伪多项式”算法——S 很大（如 10^9）时反而不可行。 S 很大时的正确替代方案是「折半搜索」（meet in the middle，O(2^(n/2))）或「集合 DP」（用 HashSet<可达子集和> 逐个元素扩展，状态数同样受 S 限制但省掉大量空区间）。 不要用「异或 + 哈希」：异或只能判断”能否分成两个等和子集”（那是本文件第 32 题 LC 416 的判定问题），而本题要最小化差值、且要求两个子集的和不必相等，异或既不刻画子集和也会丢信息（[1,2] 与 [3] 异或同为 3）。 面试加分点：意识到 O(n·S) 依赖 S 的大小，不是真正的多项式。

43. 盈利计划（LeetCode 879）

① 题意

有 K 个犯罪团伙（crime）。第 i 个团伙需要 group[i] 个工程人员，收益为 profit[i]。 求有多少种选择团伙的方案，使得：

  • 使用的工程人员总数 ≤ n
  • 总收益 ≥ minProfit

注意：选的是”整个团伙”，不是挑团伙里的某个人。 每个团伙是 01 语义（选或不选）。 人员数 n 是第一个容量维度，收益 minProfit 是第二个容量维度。

② 暴力解法与瓶颈

枚举 2^K 种团伙子集：

瓶颈：官方约束 1 ≤ group.length ≤ 100，K = 100 时 2^100 ≈ 1.3×10³⁰ 完全不可行。

官方约束：1 ≤ n ≤ 100，0 ≤ minProfit ≤ 100，1 ≤ group[i] ≤ 100，0 ≤ profit[i] ≤ 100。 由此可得 DP 规模为 K·n·minProfit ≤ 100·100·100 = 10⁶，这正是本题可解的原因。

关键观察：这是二维 01 背包计数，且收益维度的目标是”至少”而不是”恰好”——这决定了 max(0, ...) 的饱和处理。

③ 状态定义与关键转化

dp[i][j] = 用至多 i 个工程人员，收益至少为 j 的方案数

关键点说明
两个容量维度i 记人员，j 记收益
j 是”至少 j”这是本题最容易错的地方——不是”恰好”
饱和索引 max(0, j - p)当 j ≤ p 时，这个团伙本身就够，所以要求变成 0
dp[i][0] = 1（所有 i 都设）收益要求 0 → 唯一方案是”什么都不选”
答案dp[n][minProfit]（不是 sum(dp[n])）

禁忌

j 维是”至少”，所以答案是 dp[n][minProfit]，不是 Σ dp[n][j] dp[n][j] 的定义已经是”收益至少为 j”，所以 dp[n][minProfit] 单独一项就包含了所有满足条件的方案。 如果再对 j 求和，等于把”同一方案”按不同阈值重复统计。

自查：官方样例 n=5, minProfit=3, group=[2,2], profit=[2,3] 的答案是 2。 若用 Σ dp[5][j] = 4 + 3 + 3 + 2 = 12，直接错。

④ 转移方程推导

处理第 k 个团伙（需 g 人，收益 p）：

  1. 不选：dp[i][j] 保持旧值
  2. 选：剩下至多 i - g 人，收益还需 至少 j - p

为什么是

max(0, j - p) 而不是 j - p？ 状态 j 的语义是”收益至少 j”。 如果 j ≤ p，选上这个团伙后收益就已经 ≥ j 了，剩下的部分没有任何要求 → 索引 0。

如果写成 j - p（可能为负），会数组越界。 这是本题的头号 bug。

“不重不漏”论证：对第 k 个团伙”选/不选”互斥穷尽；i 逆序保证该团伙只被选一次。 注意：内层 j 的方向无所谓（读的是 dp[i-g]，不同行），但保持降序更直观。

面试追问 3：能不能用数学公式？

可以，但本题是有上界的（每个骰子点数 ≤ k），所以要走容斥原理。

推导：求 x₁ + x₂ + … + xₙ = target，其中 1 ≤ xᵢ ≤ k。 令 yᵢ = xᵢ - 1，则 0 ≤ yᵢ ≤ k-1，且 Σyᵢ = target - n（记作 S）。 先不管上界，Σyᵢ = S 的非负整数解个数是 C(S+n-1, n-1)； 再对”yᵢ ≥ k”做容斥，每选 j 个变量越界就各减 k：

[!danger] 上界是 j·k，不是 j·(k+1) 常见笔误写成 C(target - j*(k+1) - 1, n-1)。 为什么错：xᵢ 的取值区间是 [1, k]，越界条件是 xᵢ ≥ k+1； 但做变量替换 yᵢ = xᵢ - 1 之后，上界已经整体平移成 k-1， 越界条件变成 yᵢ ≥ k，每次扣掉的是 k 而不是 k+1。 两种写法只差 1，但会系统性高估答案。

反例：n=3, k=6, t=10

  • 错误式：33；正确式：27；DP：27

  • 大样例 n=30, k=30, t=500：两者都给 222616187（大样例反而测不出这个 bug）

一句话总结

“能不能重复用同一件物品”，完全由”读 dp[j-w] 时它有没有被本轮更新过”决定。

  • 逆序 → 没被更新 → 不重复（01）
  • 正序 → 已被更新 → 可重复（完全）

45.4 初值速查（第二容易忘的部分）

目标dp[0]其余初值转移前判可达？
最大值00否
最小值0INF否
方案数10否（0 天然不贡献）
可达性truefalse否

至少 + 最大值00否（= 普通背包）

统一判据

初值必须代表”空方案”的合法取值。

  • 求最大值：空方案得分 0，且 0 是下界 → min/max 正常
  • 求最小值：空方案不是合法解 → 初值要 INF
  • 求计数：空方案恰好 1 种 → dp[0] = 1
  • 求可达：空方案可达 → dp[0] = true

45.6 完整决策流程（写代码前问自己这 5 个问题）

  1. 物品能用几次？ → 决定 01 / 完全 / 多重 / 分组
  2. 容量是几维？ → 决定数组是一维还是二维
  3. 求什么？ → 决定聚合方式（max/min/+=）和初值
  4. “恰好”还是”至少/至多”？ → 决定要不要标记不可达
  5. 组合还是排列？ → 决定外层循环对象

最后三个提醒

  1. 填完表一定用暴力枚举交叉验证。 背包题的手算错误率极高，而暴力枚举几乎不会错。
  2. 注意”不可达”标记。 恰好语义必须标记，至少/至多语义不能标记。
  3. 大样例一定要跑。 很多溢出和性能问题在小样例上测不出来（如 LC 1155 的 (30,30,500)）。
