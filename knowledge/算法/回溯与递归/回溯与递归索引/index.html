回溯与递归索引

本页用途

回溯的本质是**“走一步 → 看结果 → 撤销这一步”的模板化 DFS**。代码上它和普通 DFS 几乎一样，唯一区别是多了”撤销”这一步（撤销选择、撤销标记、撤销长度）。 本主题 7 篇覆盖回溯的三个典型场景：选一个（组合）、选一个并排列（排列）、多约束剪枝（括号生成 / N 皇后）。此外 单词搜索 展示了”网格回溯”，删除无效的括号 展示了”带配额的回溯”。

读完本页你应该能自己回答：组合和排列的差别在代码上是哪一行；「撤销」在每种题里撤销的是什么；为什么 括号生成 的剪枝条件是”左不超过 n、右不超过已放左数”。

关键结论

一、回溯的通用骨架

所有回溯题都是这个循环，只是”回溯撤销”的具体内容不同：

「撤销」漏一行 = 结果里多出一堆脏数据

回溯最常见的 bug 就是忘了path.pop() 或 used[i] = false。每加一次选择就必须配一次撤销，这是死规矩。写的时候可以在注释里标成 // 撤销选择 提醒自己。

二、组合 vs 排列，差别在一行 +1

组合（组合总和）排列（全排列）
结果是否计顺序不计计
下一层从哪开始for (int i = start; ...) 从 start（不 +1，允许重复选）for (int i = 0; ...) 从 0，用 used 跳过已选的
撤销path.pop()path.pop() + used[i] = false

组合为什么从

start 开始而不是从 i+1 组合要”不重”（避免同一组合被换顺序重复枚举），所以下一层从 i 开始递进、不回退。而 组合总和 里允许同一个数重复选，所以下一层是 i 而不是 i+1。这个 +1 有没有，完全取决于题目是否允许重复——见该篇的关键细节一节。

三、剪枝：把”注定失败”的状态提前砍掉

括号生成 的两个剪枝条件是回溯里最值得学的例子，因为它们是想出来的，不是背下来的：

剪枝条件怎么想出来的代码
放的 ( 数量 < n要生成 n 对括号，左括号不能超if (leftUsed < n) dfs(..., leftUsed+1, ...)
放的 ) ≤ 已放的 (任何前缀里右括号都不能多于左括号，否则不合法if (rightUsed < leftUsed) dfs(..., leftUsed, rightUsed+1, ...)

第二个条件为什么是

rightUsed < leftUsed 而不是别的东西 因为合法括号序列的任意前缀中，右括号数都不超过左括号数。这不是”最终要配平”，而是”过程中不能先 imbalance”。这个”前缀约束”的思维是剪枝的通用来源——见 括号生成 的剪枝一节。

N 皇后 的剪枝更复杂：不是”数量约束”而是”位置冲突”，要检查三处——同列、两个方向的对角线。用三个 boolean 数组/Set 判冲突是它的核心，见该篇。

四、网格回溯：标记与回滚的时机

单词搜索 在网格上做 DFS，标记的处理和 岛屿数量 完全不同：

岛屿数量（连通分量）单词搜索（回溯）
标记时机进入时标记，不回滚进入时标记，退出时回滚
为什么一次 DFS 走完全部连通格，标记是永久的一次 DFS 只试一条路径，失败要让兄弟分支能重试这个格子

忘记回滚的典型后果

单词搜索里，某个格子可能同时是”路径 A 的第 2 步”和”路径 B 的第 1 步”。如果进入后永久标记，路径 B 就再也用不了这个格子，会漏解。回滚是回溯在网格上的核心。

五、带计数约束的回溯（删除无效的括号）

这一题比较特殊：它不是”枚举所有可能”，而是”先算出最少要删多少，再按这个额度精确枚举”。两步走：

  1. 先扫描一遍：算出有多少个多余的左括号（lToRemove）和多余的右括号（rToRemove）。
  2. DFS 按配额回溯：在递归里用 lToRemove / rToRemove 当”还能删几个”的计数器，删到 0 就不再删。

“先算配额再枚举”比”枚举所有删除方案再过滤”好在哪

后者是指数爆炸（每个括号删/不删 2^n），而且很多方案根本不合法。前者只枚举恰好删最少个的方案，规模小得多。见 删除无效的括号 的核心思想一节。
