设计与数据结构索引

本页用途

前 13 个主题是”用现成结构解一道题”，本主题是**“自己实现一个结构”。这类题是面试的最后一关，也是最能区分档次的地方——因为它没法套模板，必须从需求反推结构**。 本主题 5 篇刚好覆盖五种结构：哈希表 + 链表（LRU 缓存）、两个堆（数据流的中位数）、多层链表（设计跳表）、多叉字典树（实现 Trie（前缀树）、字典序的第K小数字）。

读完本页你应该能自己回答：LRU 为什么必须是”哈希表 + 双向链表”、单向链表为什么不行；数据流的中位数 的两个堆怎么保证大小差 ≤ 1；Trie 的空间开销在哪里、字典序的第K小数字 为什么可以跳过整棵子树。

关键结论

一、LRU = 哈希表（定位）+ 双向链表（定序）

LRU 缓存 要求 O(1) 的 get 和 put。两个操作决定了结构：

操作需求数据结构
get(key) 要 O(1) 找到节点按 key 定位HashMap
任何节点要 O(1) 移到表头摘下 + 插到头部双向链表

为什么必须是双向链表

摘除一个节点时，单向链表找不到它的前驱（只能从头遍历，O(n)）；双向链表通过 prev 指针 O(1) 找到。双向链表是 LRU 的硬性要求，不是”更好”而是”必须”。见该篇的关键细节一节。

用 dummy head / dummy tail

和 链表索引 里的 dummy head 同一个道理：删除头节点、删除尾节点时不用写特判。LRU 缓存 的代码里加了两个哨兵节点，就是为了消除这两个分支。

二、两个堆维持「大小差 ≤ 1」

数据流的中位数 的核心不变量是：

堆存什么数量
大顶堆 maxHeap较小的一半，堆顶是这半里的最大(n+1)/2
小顶堆 minHeap较大的一半，堆顶是这半里的最小n/2

为什么是「偶数取中间两个的平均、奇数取 maxHeap 堆顶」

因为 maxHeap 总是多 1 个（或者相等）。奇数时多出来的那个必然在 maxHeap 堆顶，正是中位数；偶数时两堆相等，中位数横跨两个堆顶。见该篇的核心思想一节。

复杂度不对称

addNum 是 O(log n)（堆的插入/弹出），findMedian 是 O(1)（直接取堆顶）。调用方应该按这个不对称来设计读多写少还是写多读少。见该篇的复杂度一节。

三、Trie：节点设计的两种权衡

实现 Trie（前缀树） 经典的 26 个子指针写法，代价是空间换时间：

设计空间查询速度适用
定长数组 children[26]O(字符总数 × 26)O(1) 定位子节点字符集固定且很小（26 字母）
HashMap / 链表O(字符总数)O(字符集大小)字符集大（Unicode / 数字字母混合）

面试时能提一句”如果字符集不限于 26 个字母，HashMap 版本更省空间”，会显得考虑周全。见该篇的关键细节一节。

四、跳表：用随机层数换平衡

设计跳表 的核心是每一层的节点数随机决定（以概率 p 决定节点是否晋升到上一层）：

为什么有效索引层让查找能”跳”，避免从头线性扫描
为什么要随机随机层数让树高期望 O(log n)，同时避免手写红黑树那种复杂的旋转
层数怎么定常见 p = 0.25 或 0.5，见该篇的实现

跳表 vs 红黑树

跳表最大的优势是实现简单、无需指针重平衡，且天然对顺序遍历友好。所以 Redis 的有序集合、LevelDB 的 MemTable 都用跳表而不是红黑树。

五、字典序跳步：Trie + 前缀计数

字典序的第K小数字 是本主题最难的一题，巧在不逐个枚举 1..n，而是按”跳”计数：

关键说明
不枚举每个数字逐个枚举是 O(n)（n 可到 10^9），必须整棵子树一起跳
三类情况的拆分cur 的末位是 9 / 1..8 / 0，转移完全不同，见该篇的核心思想一节
复杂度每跳一次 O(log n)，总 O((log n)²)

这题的三个”如果”必须背下来

①cur 是 1,2,...,8；② cur 是 9；③ cur 后面跟着 0。 这三种情况下”下一个前缀”和”跳过的个数”都不同，是本题的全部难点。见该篇的关键细节一节。

  • LRU 为什么必须是双向链表？单向会卡在哪一步？
  • dummy head / dummy tail 在 LRU 里消除了哪两个分支？
  • 数据流的中位数 两个堆的大小关系是什么？为什么中位数总是从 maxHeap 堆顶取？

  • 跳表为什么要用随机层数？它和红黑树相比最大的实现优势是什么？
