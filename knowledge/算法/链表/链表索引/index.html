链表索引

本页用途

链表题在真实项目里出现频率不高，但它是唯一能逼你手动管理指针的数据结构。面试官考链表，考的从来不是”你会不会写链表题”，而是你写代码时有没有分清”当前指针”和”prev 指针”——一改就错，说明基本功不牢。 本主题 5 篇全是中等题，覆盖四种基本手法：迭代双指针、递归换栈、辅助空间改写、原地重排。

读完本页你应该能自己回答：虚拟头节点到底省了什么；快慢指针的”fast 走 n 步”为什么等于倒数第 n 个；随机链表的复制 为什么必须分两趟而不能一趟完成。

关键结论

一、dummy head 省的是「头节点被删」这一个分支

链表题里几乎所有”可能删头”的场景都会挂一个虚拟头节点：

没有 dummy head有 dummy head
要在循环里写 if (cur == head) head = ...统一当作普通节点处理，代码里一个特判都没有
每道题都要重新想一遍头节点模板化，所有删除题通用

一句话

只要题目里出现”删除”，或者需要「在头节点之前插入」，就挂 dummy head。这不是技巧，是降低出 bug 概率的工程习惯。

二、快慢指针的「fast 先走 n 步」

删除链表的倒数第 N 个结点 的关键操作不是”两个指针一起走”，而是先把距离拉开：

「n 是倒数第 n 个」这个 off-by-one

fast 走 n 步后，fast 领先 slown 个节点。两指针同步走到 fast 为 null 时，slow 停在倒数第 n+1 个，也就是待删节点的前驱——这正是我们要的。如果 fast 走 n−1 步，slow 就会停在待删节点本身，还得再处理一次。 见该篇「快慢指针定位」的图解。

三、为什么 随机链表的复制 必须分两趟

这是本主题最重要的一道。它看起来像”一遍遍历建哈希表映射就行”，但有两个致命问题：

问题说明
哈希表 O(n) 空间题目要求 O(1) 空间
random 可能指向还没建的节点一趟遍历时 node.random 可能指向后面的节点，无法立刻找到对应副本

解法是先建链再拆链：

为什么”先建链再拆链”是必须的

交织之后，A'.random 可以安全地指向 B'——因为 B' 此刻已经存在（交织阶段就建好了）。拆链阶段只是”重新串接”，不涉及任何新的指针创建，所以不会有”指向不存在的节点”的问题。

四、链表上做排序：优先考虑自底向上归并

排序链表 的 O(1) 空间解法是自底向上归并：

方式过程空间
自顶向下（分治递归）先递归分成两半，再合并O(log n) 递归栈
自底向上两两合并成 2 个节点一组，再合并成 4 个……O(1)

链表上不要用快排

快排在链表上每次划分都要遍历全部节点，O(n²) 且原地交换很麻烦。归并的合并阶段天然适配链表（只需改 next，不用搬数据），这正是链表场景选归并的原因。
